# レジストリとマニフェスト

`vw2026 install <name>@<tag>` が**何を、どこから取り、どう置くか**を決める 2 つのファイルの
書き方と、プラグインの提供側に求めることの真実はこのページです。このプラグイン（`cli`）も、
ほかのプラグインも、同じ書き方で入ります。手順（付け替え・後始末・終了コード）は
[インストール](plugin/install-and-update.md)にあります。

| ファイル | 中身 | 書く人 | 置き場所 |
| --- | --- | --- | --- |
| レジストリ | 名前 → マニフェストの場所の規則 | このリポジトリ（既定のレジストリ）・呼ぶ側（追加のレジストリ） | 既定のものは CLI に埋め込む。追加のものは `--registry` で渡す |
| マニフェスト（`vw2026.json`） | 1 つのリリースのタグ・ターゲットごとの資産・sha256・フック | プラグインの提供側（CI） | 提供側が決める（レジストリの規則が指す） |

- **2 つに分けるのは、変わる頻度と書く人が違うためです。** 名前とリリースの置き場所はほとんど
  変わらず、受け入れるかをこのリポジトリが決めます。資産とハッシュはリリースのたびに変わり、
  提供側が持ちます。
- **GitHub に依りません。** レジストリとマニフェストは URL かパスで指すだけで、GitHub の API は
  使いません。GitHub のリリース・静的な Web サーバー・社内のファイル共有のどれにも置けます。
- **認証は持ちません。** 取れるのは、認証なしの `https://` と、OS の権限で読めるパスだけです
  （非公開のプラグインは、利用者だけが読めるファイル共有などに置く）。
- 形式は JSON です（Go の標準ライブラリで読める。外部の依存を足さない）。
- **互換（3 つのファイルで同じ）**: 知らない項目は無視し、知らない版（`registry_version`・
  `manifest_version`・`record_version`）は失敗にします。
  - **項目を足すだけで、古い CLI が無視しても正しく動く変更では、版を上げません**（入っている CLI が
    `install cli@latest` で更新できなくならないため）。
  - **古い CLI が無視すると誤って入れる・誤って消す変更のときだけ、版を上げます**（古い CLI に黙って
    半端に扱わせないため）。
  - `manifest_version` を上げたリリースは、それを読めない古い CLI では入れられません。利用者は
    **初回のスクリプトで入れ直して CLI を更新します**（一時フォルダの CLI は新しいので読める。
    [インストール「初回のスクリプト」](plugin/install-and-update.md#初回のスクリプトget-vw2026sh--ps1)）。
    `cli` のマニフェストの版を上げるときは、そのことをリリースの説明に書きます。

## 名前・タグ・ターゲット

| 値 | 使える文字 | 補足 |
| --- | --- | --- |
| 名前 | `[a-z0-9-]`。先頭と末尾は英数字。64 文字まで | **プラグインのフォルダ名にもなる**（`<Plug-Ins>/<name>/`）。小文字だけなのは、mac と Windows が大文字と小文字を区別しないため。Windows の予約された名前（`con`・`nul`・`aux`・`prn`・`com0`〜`com9`・`lpt0`〜`lpt9`）は使えない |
| タグ | `[A-Za-z0-9][A-Za-z0-9._-]*`（先頭は英数字）。128 文字まで（このプラグインの PR のタグは slug を切り詰めて収める。[名前と識別子](plugin/identifiers.md)） | `@` の後ろに必ず書く（既定のタグは持たない）。URL やパスに埋め込んでも、外へ出たり逃がしが要ったりしない文字だけにする。先頭を英数字に限るのは、`.`・`..` だけのタグが `{tag}` の置き換えで上の階層を指さないようにするため |
| ターゲット | `macos-arm64` / `macos-x64` / `windows-x64` | CLI が**計算機**から 1 つに決める（動いているプロセスの種類では決めない）。mac は `sysctl hw.optional.arm64` が 1 なら `macos-arm64`、それ以外は `macos-x64`（mac の CLI は universal なので、Rosetta の下の端末から走らせると x86_64 として動くが、Vectorworks は arm64 で動くため）。Windows は `windows-x64`（Windows on ARM でも Vectorworks は x64 のエミュレーションで動く） |

**タグは使い回しません。** 1 つのリリースに 1 つのタグを付け、同じタグを別のリリースに付け直しません
（提供側の約束。CLI は確かめられない）。入っているものと同じタグなら同じものとみなし、zip を取り直さず、
フォルダも付け替えずに `install` のフックだけを走らせ直して `up_to_date` で終わります。

最新を指す名前（`latest`・`stable` など）は、**提供側が置き場所で用意します**。レジストリは別名を
知らず、`@` の後ろの文字列でどの規則を使うかを決めるだけです（下記「規則の選び方」）。

## レジストリ

```json
{
  "registry_version": 1,
  "plugins": {
    "cli": {
      "manifests": [
        { "match": "latest", "path": "https://github.com/min-nano/vectorworks-plugin-command-line-interface/releases/latest/download/vw2026.json" },
        { "match": "*", "path": "https://github.com/min-nano/vectorworks-plugin-command-line-interface/releases/download/{tag}/vw2026.json" }
      ]
    },
    "in-house-tool": {
      "manifests": [
        { "match": "stable", "path": "\\\\fileserver\\vectorworks\\in-house-tool\\stable.json" },
        { "match": "*", "path": "\\\\fileserver\\vectorworks\\in-house-tool\\{tag}\\vw2026.json" }
      ]
    }
  }
}
```

| 項目 | 意味 |
| --- | --- |
| `plugins` | 名前 → 項目 |
| `manifests` | 規則の配列。1 つ以上 |
| `match` | `@` の後ろの文字列と照らすパターン。使える文字はタグと同じ文字に `*`（0 文字以上に合う）を足したもの。全体が一致したときだけ合う |
| `path` | マニフェストの場所。`https://` の URL か絶対パス。`{tag}` を書くと `@` の後ろの文字列に置き換わる |

### 規則の選び方

- **先頭から順に `match` を照らし、最初に合った 1 つだけを使います。** 取るのはその 1 つだけで、
  取れなければ（見つからないを含む）次の規則へ進まずに失敗にします。どの場所を使うかが文字列だけで
  決まり、ネットワークの状態で変わらないためです。
- どの規則にも合わなければ、何も取らずに失敗にします。
- **`path` に `{tag}` があれば、取ったマニフェストの `tag` がその文字列と一致することを求めます**
  （タグで直接指す規則なので、違えば規則か置き場所の誤り）。`{tag}` が無い規則（`latest` のように
  決まった場所を指すもの）では、マニフェストの `tag` をそのまま使います。出力には指定した文字列
  （`requested`）と使ったタグ（`tag`）の両方を載せます。

### レジストリの順

| 順 | レジストリ | 補足 |
| --- | --- | --- |
| 1 | **既定のレジストリ**（CLI に埋め込む。`cli/internal/registry/default.json`） | 必ず先頭にあり、外せない。このリポジトリの PR で直し、CLI のビルドに入る |
| 2〜 | `--registry <url\|path>`（何度でも書ける。環境変数 `VW2026_REGISTRY` は 1 つだけ。どちらも `,` で区切らない。URL やパスの `,` をそのまま使うため） | 書いた順に引く。引数があれば環境変数は読まない（2 つの一覧をつながない）。`https://` でない `<scheme>://`（`http://`・`HTTPS://` など）は、パスとして扱わずに使い方の誤りにする |

- **先に見つかった名前を使います。** 名前が重なっても失敗にしません。どのレジストリの項目を
  使ったかは出力の `registry` に載せます。
- **既定のレジストリにある名前は上書きできません。** `cli` はいつもこのリポジトリを指します。
- **前から順に取り、名前が見つかった時点で止めます。** 名前が見つかる前に取れない・読めない
  レジストリがあれば、そこで失敗にします（飛ばすと、どの項目が勝つかがネットワークの状態で変わる）。
  1 つのレジストリの中に正しくない項目があれば、そのレジストリ全体を読めないものとして扱います。
- `https://` で取ったレジストリの `path` は `https://` だけにできます（遠くのレジストリが利用者の
  手元のパスを指さないため）。手元のファイルのレジストリは、どちらも書けます。
- `,` を含む URL やパスは、環境変数では渡せません（引数で渡す）。
- **既定のレジストリを埋め込むのは**、`install cli` がレジストリの取得に左右されないこと、PR の
  プレリリースにその PR のレジストリが入り、足した項目をそのまま試せること、CLI とレジストリが
  必ず同じコミットのものになることのためです。新しいプラグインは、`vw2026 install cli@latest` で
  CLI を更新したあとから使えます。

## マニフェスト（`vw2026.json`）

```json
{
  "manifest_version": 1,
  "tag": "0.0.0-a1b2c3d",
  "targets": {
    "macos-arm64": {
      "asset": "https://github.com/min-nano/vectorworks-plugin-command-line-interface/releases/download/0.0.0-a1b2c3d/cli-macos-arm64.zip",
      "sha256": "…",
      "hooks": {
        "install": ["sh", "hooks/install.sh"],
        "uninstall": ["sh", "hooks/uninstall.sh"]
      }
    },
    "windows-x64": {
      "asset": "https://github.com/min-nano/vectorworks-plugin-command-line-interface/releases/download/0.0.0-a1b2c3d/cli-windows-x64.zip",
      "sha256": "…",
      "hooks": {
        "install": ["powershell", "hooks/install.ps1"],
        "uninstall": ["powershell", "hooks/uninstall.ps1"]
      }
    }
  }
}
```

| 項目 | 意味 |
| --- | --- |
| `tag` | このリリースのタグ（使い回さない） |
| `targets` | ターゲット → 資産。今のターゲットが無ければ「この環境には非対応」として何も変えずに失敗にする |
| `asset` | zip の場所。**絶対の参照**（`https://` の URL か絶対パス）。`https://` で取ったマニフェストの `asset` は `https://` だけ |
| `sha256` | zip の SHA-256（16 進の小文字 64 桁）。**必須**。取った zip と合わなければ何も変えずに失敗にする |
| `hooks` | 省略できる。`install` と `uninstall` のそれぞれを省略できる（下記「フック」） |

- 参照を絶対にするのは、同じマニフェストを別名の場所（`stable.json` など）に写しても、指す資産が
  変わらないようにするためです（相対の参照は、写した場所から解決されて外れる）。
- GitHub の `releases/latest/download/…` のような転送は追います。転送の先も `https://` に限ります。

### zip の形

- **直下に、そのターゲットのモジュールがちょうど 1 つ**あること（mac は `*.vwlibrary` のフォルダ（バンドル）、
  Windows は `*.vlb` のファイル）。無い・2 つ以上・フォルダかファイルかが違うなら失敗にします（Vectorworks が
  読み込めない形を入れない）。名前は記録に残し、`uninstall` の安全弁に使います。
- zip の中身は、そのまま `<Plug-Ins>/<name>/` に置きます（ファイル名を列挙しない）。展開では権限
  （実行ビット）を保ちます。ファイルの時刻は zip の項目のものに戻さず、展開した時刻のままにします（組み立ては
  OS の一時フォルダの下で行うので、古い時刻を付けると、付け替えの前に OS の片付けで消されうるため。
  [インストール「作業の場所」](plugin/install-and-update.md#作業の場所)）。
- **失敗にするもの**: シンボリックリンク・絶対パスや `..` を含む項目（展開先の外へ出る）・`\` を
  区切りに使った項目（区切りは `/` に限る。Windows PowerShell 5.1 の `Compress-Archive` が作る形）・
  512 MiB を超える zip（終わらない本文で `<Plug-Ins>` と同じドライブを埋めないため）・展開すると合計で 2 GiB を
  超える zip（小さな zip が大きく展開されて同じドライブを埋めないため。展開する前に、項目に書かれた大きさの
  合計で断る）。`./` で始まる項目
  （`zip -r x.zip ./` が作る形）は、`./` を除いた名前として扱います。

## フック

**プラグインのフォルダの外に何かを置くプラグインは、その置き方と片付け方をフックに書きます。**
このプラグインは、PATH をフックで置きます（CLI とスプールはフォルダの中にある。[インストール「`cli` のフック」](plugin/install-and-update.md#cli-のフック)）。

- **フックは、Vectorworks の承認より前に、利用者の権限で走ります。** プラグインのコードは、
  Vectorworks の「開発元不明のプラグイン」のダイアログで有効にしたあとでしか走りませんが、フックは
  `install` の中ですぐに走り、この同意を通りません。**レジストリを引くことは、そのレジストリが指す
  提供側のフックを走らせることに同意することです。** 既定のレジストリの項目は、このリポジトリの
  レビューを通ったものだけですが、**レビューは項目（名前と置き場所の規則）を載せるときだけで、その後の
  リリースのマニフェストやフックには及びません。** 提供側は後のリリースでフックを自由に変えられ、
  `@latest` を入れる利用者は、このリポジトリの誰も見ていないフックを走らせます。既定のレジストリに
  載せることは、その提供側を信頼すると決めたという意味です。`--registry` で足すレジストリを信頼
  できるかは、呼ぶ側が決めます。
- sha256 は、取った zip がマニフェストの書いたものと同じこと（途中で壊れていない・すり替わって
  いない）を確かめるだけです。マニフェストを書く提供側そのものを信頼できるかの裏付けにはなりません。
- フックのコードは zip の中に限ります（下記「書き方」）。マニフェストに直接コマンドを書けないので、
  走るものは sha256 で照らした zip の中身だけです。
- **決まったときにだけ動きます。** `install` と `uninstall` の中で、**ロックを掴んでいる Vectorworks が
  居ないときだけ**走ります（常駐の中で勝手に動く処理にはならない。[設計「本番で常駐させる前提」](design.md#本番で常駐させる前提安全)）。
  ロックを掴んでいない Vectorworks（`cli` が入っていない・無効・起動の途中・2 つ目の起動）は見分け
  られないので、**Vectorworks が止まっていることの保証にはなりません**（[インストール「流れ」](plugin/install-and-update.md#流れ)）。
  フックは、Vectorworks が動いていても壊れないように書きます。

### 書き方

- 引数の配列で書き、シェルを通しません。
- 1 つ目は次のどれかです。PATH からは探しません。

  | 1 つ目 | 走るもの | 2 つ目 |
  | --- | --- | --- |
  | `sh` | `/bin/sh`（mac） | **zip の中のスクリプトの相対パス**（必須） |
  | `powershell` | System32（`FOLDERID_System`。環境変数 `SystemRoot` は読まない）の `WindowsPowerShell\v1.0\powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File`（Windows。Windows PowerShell 5.1） | **zip の中のスクリプトの相対パス**（必須） |
  | zip の中の相対パス | その実行ファイル | — |

- zip の中の相対パスは、展開したフォルダの中に実在するファイルでなければ失敗にします（絶対パス・
  `..`・`-` で始まるもの（`sh -c` のような指定）は断る）。それより後ろの引数は、そのまま渡す文字列です。
- **管理された Windows では、`powershell` のフックが走らないことがあります。** グループポリシー
  （MachinePolicy / UserPolicy）で実行ポリシーを `AllSigned` にした PC では `-ExecutionPolicy Bypass` が
  効かず、AppLocker / WDAC による Constrained Language Mode では `Add-Type` も止まります。そうした PC
  では `powershell` のフックを持つプラグイン（`cli` を含む）は入れられません（`install` はフックの失敗
  としてフォルダを戻す）。対応はしません。

- 作業ディレクトリはプラグインのフォルダ（`<Plug-Ins>/<name>/`）です。標準入力は閉じて渡し、
  標準エラーは CLI の標準エラーへそのまま流します。
- **標準出力は、空か、UTF-8 で書いた JSON のオブジェクト 1 つ**にします。`install` / `uninstall` の出力の
  `hook` にそのまま載ります。それ以外（正しくない UTF-8・2 つ以上の値・JSON でない行）を出したら、
  終了コードが 0 でもフックの失敗として扱います（先頭の BOM と前後の空白は許す）。
  - Windows PowerShell 5.1 は、リダイレクトされた標準出力を OEM のコードページ（日本語の Windows なら
    CP932）で書きます。`powershell` のフックは最初に `[Console]::OutputEncoding = [Text.UTF8Encoding]::new($false)`
    とし、JSON は `[Console]::Out.Write(...)` で 1 度だけ書きます。
  - パイプラインに残った値（`New-Item`・`Add-Type` などの戻り値）も標準出力に出るので、`| Out-Null` か
    `[void]` で捨てます。進み具合などは標準エラーへ書きます。
- 時間の上限は持ちません（CLI は待つ上限を決めない。止めるのは呼ぶ側）。

### いつ走るか

| フック | とき | 失敗（0 以外で終わった・標準出力が JSON でない）したとき |
| --- | --- | --- |
| `install` | プラグインのフォルダを付け替えたあと、後始末の前。最初に入れるときも更新のときも。**入っているものと同じタグのときは、zip を取らず、付け替えもせずに、記録に写したフックを入っているフォルダで走らせる**（フォルダの外に置いたものを置き直すため） | フォルダを元に戻して失敗で終わる（同じタグのときは、フォルダは変えていないのでそのまま）。フックがフォルダの外で変えたものは CLI には戻せない |
| `uninstall` | フォルダを `<Work>/old/<name>/` へ移したあと、消す前。**入っている版の**フック（記録に写したもの）を、移した先のフォルダで走らせる（`VW2026_HOOK_PLUGIN_DIR` も移した先。もとの場所は `VW2026_HOOK_INSTALL_DIR`） | フォルダを `<Plug-Ins>/<name>/` へ戻し、何も消さずに失敗で終わる |

- **フックは、何度走っても同じ結果になるように書きます**（失敗のあとに走らせ直しても、
  同じタグの `install` で走らせ直しても壊れないため）。
- **`uninstall` のフックは、外のものを消し始めたあとは失敗にしません。** 失敗にすると CLI がフォルダを
  戻すので、外のものだけが消えた状態になります。確かめられることは消す前に確かめて失敗にし、消し始めた
  あとに消せなかったものは標準出力の JSON に載せて 0 で終わります。
- **更新のときに古い版の `uninstall` は走らせません。** 新しい版の `install` に前のタグを渡すので、
  前の版が置いたものの移し替えは新しい版が受け持ちます（消してから置き直すと、その間 CLI が
  無くなるなど、片付けと置き直しの間に穴ができるため）。
- **古い版へ戻すとき**（`@<古いタグ>`）も同じで、古い版の `install` は新しい版が外に置いたものを
  知りません。そのため、**フックがフォルダの外に置くものの名前と場所は、版をまたいで変えない**
  ようにします（どの版の `uninstall` でも片付けられるように）。変えた場合、戻したあとに新しい版の
  置いたものが残りうることは、提供側の責任として受け入れます。

### フックに渡す環境変数

| 変数 | 中身 |
| --- | --- |
| `VW2026_HOOK_NAME` | 名前 |
| `VW2026_HOOK_TAG` | `install` は入れるタグ、`uninstall` は入っているタグ |
| `VW2026_HOOK_PREVIOUS_TAG` | `install` のとき、前に入っていたタグ（最初に入れるときは空） |
| `VW2026_HOOK_TARGET` | ターゲット |
| `VW2026_HOOK_PLUGIN_DIR` | いまプラグインのファイルがあるフォルダ（作業ディレクトリと同じ）。`install` は `<Plug-Ins>/<name>/`、`uninstall` は移した先の `<Work>/old/<name>/` |
| `VW2026_HOOK_INSTALL_DIR` | プラグインが入る・入っていたフォルダ（`<Plug-Ins>/<name>/`）。`install` では `VW2026_HOOK_PLUGIN_DIR` と同じ。`uninstall` で、フォルダの中を指すもの（PATH など）を片付けるために使う |

- **`vw2026` は、フックがフォルダの外に使える場所を用意しません**（持続する `vw2026` の場所を持たない。
  [インストール「作業の場所」](plugin/install-and-update.md#作業の場所)）。フォルダの外に置いたもの（PATH など）を
  片付けるのは、提供側の `uninstall` のフックの責任です。要るプラグインが出てきたら、場所と片付け方を
  決めて足します（環境変数を足すことは互換の変更）。
- `VW2026_HOOK_` で始まる名前は、CLI の指定の環境変数（`CLAUDE.md`「Go」）と重ならないように、
  `hook` という名前のコマンドを作りません。

## 入れたときの記録

入れたプラグインのフォルダに `vw2026-install.json` を置きます（`<Plug-Ins>/<name>/vw2026-install.json`）。

```json
{
  "record_version": 1,
  "name": "cli",
  "registry": "default",
  "tag": "0.0.0-a1b2c3d",
  "target": "macos-arm64",
  "module": "cli.vwlibrary",
  "hooks": { "install": ["sh", "hooks/install.sh"], "uninstall": ["sh", "hooks/uninstall.sh"] }
}
```

| 項目 | 使うところ |
| --- | --- |
| `name` | `uninstall` の安全弁（フォルダ名と一致すること） |
| `registry` | 同じ名前のフォルダが別の出どころのものでないかを確かめる。既定のレジストリは `default`、それ以外は `--registry` に渡した URL か絶対パス（相対パスは今の作業ディレクトリから絶対にし、`.`・`..`・重なった区切りを整えて残す）。**比べるのは、この整えた文字列どうしだけ**です（URL は大文字と小文字も含めてそのまま）。同じファイルを別の書き方（UNC と割り当てたドライブ・シンボリックリンク・名前の変わったファイル共有）で指すと別の出どころとみなして断るので、利用者は毎回同じ書き方で渡します |
| `tag`・`target` | 新しいかの判定（両方が一致すれば zip を取らず、フックだけを走らせて `up_to_date`）。`target` も比べるのは、同じタグでも別のターゲットの資産は別物のため |
| `module` | `uninstall` の安全弁（フォルダの中に実在すること） |
| `hooks.install` | 同じタグの `install` で走らせるフック（入っている版のもの。マニフェストを取り直さない） |
| `hooks.uninstall` | `uninstall` で走らせるフック（入っている版のもの） |

- **記録はプラグインのフォルダの中にだけ置きます。** 別の場所に記録ファイルを持たず、`--plugins-dir`
  も記録しません（[設計「決めたこと」](design.md#決めたこと)）。
- 記録は組み立ての場所で zip の中身と一緒に置き、フォルダと一緒に付け替えます（付け替えの途中で
  失敗して元に戻すと、記録も前のものに戻る）。
- **互換**: 冒頭の決まりのとおり、知らない項目は無視し、`record_version` は古い CLI が読むと誤る変更の
  ときだけ上げます（後の CLI が書いた記録を、`cli@<古いタグ>` で戻した古い CLI も読めるように）。
  `record_version` を上げたビルドより前へ戻すには、新しい CLI で `uninstall` してから、古いタグの
  初回のスクリプトで入れます。

## 提供側に求めること

自動で入れられるのは、次をすべて満たすプラグインだけです。満たさないプラグインは、利用者が手で
入れます（`vw2026` は手で入れたフォルダに触れない）。

- **レジストリに載っていること**（既定のレジストリならこのリポジトリへの PR。または利用者が渡す
  レジストリ）。
- **規則が指す場所にマニフェストがあり、資産は絶対の参照で、sha256 が書いてあること。**
- **タグを使い回さないこと。** 最新を指す名前が要るなら、置き場所で用意する（GitHub のリリース
  なら `releases/latest/download/vw2026.json` が下書きでもプレリリースでもない最新を指す。それ以外の
  名前は、提供側が書き換えるファイルで用意する）。
- **フォルダ名に依存しないこと。** フォルダ名はレジストリの名前で決まり、提供側は選べません。
  自分のファイルは、モジュール自身の場所から相対で見つけます。
- **残したいものをプラグインのフォルダに書かないこと。** 更新でフォルダごと入れ替わり、`uninstall` で
  フォルダごと消えます。Vectorworks が動いている間だけ要るもの（`cli` のスプールなど）は置いてかまいません
  （更新と `uninstall` は Vectorworks が止まっている間にしか行わない）。残したいもの（設定など）は
  フォルダの外の提供側が決めた場所に置き、`uninstall` のフックで片付けます。
- **モジュールのファイル名を版をまたいで変えないこと。** Vectorworks は署名の無いプラグインの
  「有効化」をモジュールのフルパスで覚えるので、名前が変わると利用者は有効化をやり直すことに
  なります（[Findings「Plug-in Modules」](https://github.com/min-nano/vectorworks-developer-sdk-reference/blob/main/Findings/Plug-in%20Modules.md)の「開発元不明のプラグイン」のダイアログ）。
- **自分のインストーラ・アップデータと併用しないこと。** `vw2026` で入れたものは `vw2026` で更新します。

**同じプラグインを二重に入れないのは利用者の責任です。** 同じプラグインが 2 つあるときに Vectorworks が
何をもって衝突とみなすかは、SDK リファレンスで確かめられていません（`Findings/` に記載が無い）。
衝突しうる値（ユニバーサル名・拡張機能の UUID・リソースの識別子）はどれもコードが登録のときに渡すもので、
外から読める識別子もありません。確かめられていない挙動に頼る判定を作らないため、`vw2026` は
ファイル名などで中途半端に見分けることをしません（判定を作らないので、この調査は実装を待たせない。
[SDK の調査](sdk-research.md)）。防ぐのは、同じ名前のフォルダへの
上書きだけです（[インストール「入れる先のフォルダ」](plugin/install-and-update.md#入れる先のフォルダ)）。
