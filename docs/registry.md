# レジストリとマニフェスト

`vw2026 install <name>@<tag>` が**何を、どこから取得し、どのように配置するか**を定める 2 つのファイルの
記法と、プラグインの提供側への要件については、このページが真実です。本プラグイン（`cli`）も、
他のプラグインも、同一の記法でインストールされます。手順（置換・後処理・終了コード）は
[インストール](plugin/install-and-update.md)に記載しています。

| ファイル | 内容 | 記述者 | 配置場所 |
| --- | --- | --- | --- |
| レジストリ | 名前 → マニフェストの場所の規則 | 本リポジトリ（既定のレジストリ）・呼び出し元（追加のレジストリ） | 既定のものは CLI に埋め込む。追加のものは `--registry` で渡す |
| マニフェスト（`vw2026.json`） | 1 つのリリースのタグ・ターゲット単位の資産・sha256・フック | プラグインの提供側（CI） | 提供側が定める（レジストリの規則が指す） |

- **2 つに分割するのは、変更の頻度と記述者が異なるためです。** 名前とリリースの配置場所はほぼ
  変わらず、受け入れるか否かを本リポジトリが決定します。資産とハッシュはリリースの度に変わり、
  提供側が保持します。
- **GitHub に依存しません。** レジストリとマニフェストは URL かパスで指すのみで、GitHub の API は
  使用しません。GitHub のリリース・静的な Web サーバー・社内のファイル共有のいずれにも配置できます。
- **認証は保持しません。** 取得できるのは、認証なしの `https://` と、OS の権限で読み取れるパスのみです
  （非公開のプラグインは、利用者のみが読み取れるファイル共有などに配置する）。
- 形式は JSON です（Go の標準ライブラリで読み取れる。外部の依存を追加しない）。
- **互換性（3 つのファイルで共通）**: 未知の項目は無視し、未知の版（`registry_version`・
  `manifest_version`・`record_version`）は失敗とします。
  - **項目を追加するのみで、古い CLI が無視しても正しく動作する変更では、版を上げません**（インストール済みの
    CLI が `install cli@latest` で更新できなくなることを防ぐため）。
  - **古い CLI が無視すると誤ってインストールする・誤って削除する変更の場合のみ、版を上げます**（古い CLI に
    黙って不完全に扱わせないため）。
  - `manifest_version` を上げたリリースは、それを読み取れない古い CLI ではインストールできません。利用者は
    **初回スクリプトで再インストールして CLI を更新します**（一時フォルダの CLI は新しいので読み取れる。
    [インストール「初回スクリプト」](plugin/install-and-update.md#初回スクリプトget-vw2026sh--ps1)）。
    `cli` のマニフェストの版を上げる場合は、その旨をリリースの説明に記述します。

## 名前・タグ・ターゲット

| 値 | 使用できる文字 | 補足 |
| --- | --- | --- |
| 名前 | `[a-z0-9-]`。先頭と末尾は英数字。64 文字まで | **プラグインのフォルダ名にもなる**（`<Plug-Ins>/<name>/`）。小文字のみなのは、mac と Windows が大文字と小文字を区別しないため。Windows の予約名（`con`・`nul`・`aux`・`prn`・`com0`〜`com9`・`lpt0`〜`lpt9`）は使用できない |
| タグ | `[A-Za-z0-9][A-Za-z0-9._-]*`（先頭は英数字）。128 文字まで（本プラグインの PR のタグは slug を切り詰めて収める。[名前と識別子](plugin/identifiers.md)） | `@` の後ろに必ず記述する（既定のタグは設けない）。URL やパスに埋め込んでも、外部へ出たりエスケープが必要になったりしない文字のみとする。先頭を英数字に限るのは、`.`・`..` のみのタグが `{tag}` の置換で上位の階層を指さないようにするため |
| ターゲット | `macos-arm64` / `macos-x64` / `windows-x64` | CLI が**計算機**から 1 つに決定する（実行中のプロセスの種類では決定しない）。mac は `sysctl hw.optional.arm64` が 1 なら `macos-arm64`、それ以外は `macos-x64`（mac の CLI は universal なので、Rosetta 下の端末から実行すると x86_64 として動作するが、Vectorworks は arm64 で動作するため）。Windows は `windows-x64`（Windows on ARM でも Vectorworks は x64 のエミュレーションで動作する） |

**タグは再利用しません。** 1 つのリリースに 1 つのタグを付け、同一のタグを別のリリースに付け直しません
（提供側の約束。CLI は検証できない）。インストール済みのものと同一のタグであれば同一のものとみなし、zip を
再取得せず、フォルダも置換せずに `install` のフックのみを再実行して `up_to_date` で終了します。

最新を指す名前（`latest`・`stable` など）は、**提供側が配置場所で用意します**。レジストリは別名を
関知せず、`@` の後ろの文字列でどの規則を使用するかを決定するのみです（下記「規則の選択」）。

## レジストリ

```json
{
  "registry_version": 1,
  "plugins": {
    "cli": {
      "manifests": [
        { "match": "latest", "path": "https://github.com/min-nano/vectorworks-plugin-command-line-interface/releases/latest/download/vw2026.json" },
        { "match": "*", "path": "https://github.com/min-nano/vectorworks-plugin-command-line-interface/releases/download/{tag}/vw2026.json" }
      ]
    },
    "in-house-tool": {
      "manifests": [
        { "match": "stable", "path": "file://fileserver/vectorworks/in-house-tool/stable.json" },
        { "match": "*", "path": "file://fileserver/vectorworks/in-house-tool/{tag}/vw2026.json" }
      ]
    }
  }
}
```

`in-house-tool` の例は Windows の共有フォルダ（`\\fileserver\vectorworks\…`）を指します。`file://` を指せるのは、
ローカルのファイル（`file://`）のレジストリのみです（下記「[参照の記法](#参照の記法)」）。

| 項目 | 意味 |
| --- | --- |
| `plugins` | 名前 → 項目 |
| `manifests` | 規則の配列。1 つ以上 |
| `match` | `@` の後ろの文字列と照合するパターン。使用できる文字はタグと同じ文字に `*`（0 文字以上に一致する）を加えたもの。全体が一致した場合のみ一致とみなす |
| `path` | マニフェストの場所。`https://` か `file://` の URL（下記「[参照の記法](#参照の記法)」）。`{tag}` を記述すると `@` の後ろの文字列に置換される |

### 参照の記法

**レジストリ・マニフェスト・資産の場所は、いずれも `https://` か `file://` の URL で記述します**（`--registry`・
`VW2026_REGISTRY`・レジストリの `path`・マニフェストの `asset`）。パスを直接記述する形式は設けません。
記法を 1 つに統一して値の判別で迷わないようにするためと、URL は空白を含まないので、空白で区切って複数を
渡せるようにするためです（下記「[レジストリの優先順位](#レジストリの優先順位)」）。

| 記法 | 指すもの |
| --- | --- |
| `https://host/path` | リモートのファイル。転送には追従し、転送先も `https://` に限る |
| `file:///Users/me/plugins.json` | mac・Linux のローカルのファイル |
| `file:///C:/Users/me/plugins.json` | Windows のローカルのファイル（区切りは `/`） |
| `file://server/share/plugins.json` | Windows の共有フォルダ（`\\server\share\plugins.json`） |

- パス中の空白・`%`・ASCII 以外の文字（日本語など）は `%XX` で記述します（空白は `%20`）。そのまま
  記述した空白は拒否します。
- `file://localhost/…` は `file:///…` と同等です。mac・Linux ではホストを記述できません。クエリ（`?…`）・
  フラグメント（`#…`）の付いたもの、相対のもの（`file:plugins.json`）は拒否します。
- `http://`・`HTTPS://`（大文字）・他の scheme・パスをそのまま記述したもの・ホストの無い `https://` は、使用方法の
  誤りとします（`--registry` に渡したものも、レジストリとマニフェスト内の参照も、同一の検証を経る）。
- `https://` で取得したレジストリとマニフェスト内の参照は、`https://` のみに限られます（リモートのファイルが
  利用者のローカルのファイルを指さないようにするため）。ローカルのファイル（`file://`）のレジストリとマニフェストは、
  どちらも記述できます。

### 規則の選択

- **先頭から順に `match` を照合し、最初に一致した 1 つのみを使用します。** 取得するのはその 1 つのみで、
  取得できなければ（見つからない場合を含む）次の規則へ進まずに失敗とします。どの場所を使用するかが文字列のみで
  決まり、ネットワークの状態で変わらないようにするためです。
- いずれの規則にも一致しなければ、何も取得せずに失敗とします。
- **`path` に `{tag}` があれば、取得したマニフェストの `tag` がその文字列と一致することを要求します**
  （タグで直接指す規則なので、異なれば規則か配置場所の誤り）。`{tag}` の無い規則（`latest` のように
  固定の場所を指すもの）では、マニフェストの `tag` をそのまま使用します。出力には指定した文字列
  （`requested`）と使用したタグ（`tag`）の両方を記載します。

### レジストリの優先順位

| 順 | レジストリ | 補足 |
| --- | --- | --- |
| 1 | **既定のレジストリ**（CLI に埋め込む。`cli/internal/registry/default-vw2026.json`。2025 の CLI は `default-vw2025.json`。[版](plugin/editions.md)） | 必ず先頭にあり、除外できない。本リポジトリの PR で修正し、CLI のビルドに含まれる |
| 2〜 | `--registry` で渡したもの（任意の数。指定・環境変数の記法は `vw2026 help install`） | 記述した順に参照する。`https://` か `file://` の URL のみを受け付ける（[参照の記法](#参照の記法)。名前が既定のレジストリにあって参照しない場合も、記法は検証する）。いずれのレジストリにも無ければ、参照したレジストリを `message` に示す |

- **先に見つかった名前を使用します。** 名前が重複しても失敗としません。どのレジストリの項目を
  使用したかは出力の `registry` に記載します。
- **既定のレジストリにある名前は上書きできません。** `cli` は常に本リポジトリを指します。
- **前から順に取得し、名前が見つかった時点で停止します。** 名前が見つかる前に取得できない・読み取れない
  レジストリがあれば、その時点で失敗とします（飛ばすと、どの項目が優先されるかがネットワークの状態で変わる）。
  1 つのレジストリ内に不正な項目があれば、そのレジストリ全体を読み取れないものとして扱います。
- `https://` で取得したレジストリの `path` は `https://` のみに限られます（上記「参照の記法」）。
- **既定のレジストリを埋め込むのは**、`install cli` がレジストリの取得に左右されないこと、PR の
  プレリリースにその PR のレジストリが含まれ、追加した項目をそのまま試験できること、CLI とレジストリが
  必ず同一のコミットのものになることのためです。新しいプラグインは、`vw2026 install cli@latest` で
  CLI を更新した後から使用できます。

## マニフェスト（`vw2026.json`）

```json
{
  "manifest_version": 1,
  "tag": "0.0.0-a1b2c3d",
  "targets": {
    "macos-arm64": {
      "asset": "https://github.com/min-nano/vectorworks-plugin-command-line-interface/releases/download/0.0.0-a1b2c3d/cli-macos-arm64.zip",
      "sha256": "…",
      "hooks": {
        "install": ["sh", "hooks/install.sh"],
        "uninstall": ["sh", "hooks/uninstall.sh"]
      }
    },
    "windows-x64": {
      "asset": "https://github.com/min-nano/vectorworks-plugin-command-line-interface/releases/download/0.0.0-a1b2c3d/cli-windows-x64.zip",
      "sha256": "…",
      "hooks": {
        "install": ["powershell", "hooks/install.ps1"],
        "uninstall": ["powershell", "hooks/uninstall.ps1"]
      }
    }
  }
}
```

| 項目 | 意味 |
| --- | --- |
| `tag` | 本リリースのタグ（再利用しない） |
| `targets` | ターゲット → 資産。現在のターゲットが無ければ「この環境には非対応」として何も変更せずに失敗とする |
| `asset` | zip の場所。`https://` か `file://` の URL（上記「[参照の記法](#参照の記法)」）。`https://` で取得したマニフェストの `asset` は `https://` のみ |
| `sha256` | zip の SHA-256（16 進の小文字 64 桁）。**必須**。取得した zip と一致しなければ何も変更せずに失敗とする |
| `hooks` | 省略可能。`install` と `uninstall` のそれぞれを省略できる（下記「フック」） |

- 参照を絶対参照とするのは、同一のマニフェストを別名の場所（`stable.json` など）に複製しても、指す資産が
  変わらないようにするためです（相対の参照は、複製先の場所から解決されて外れる）。
- GitHub の `releases/latest/download/…` のような転送には追従します。転送先も `https://` に限ります。

### zip の構成

- **直下に、そのターゲットのモジュールが丁度 1 つ**存在すること（mac は `*.vwlibrary` のフォルダ（バンドル）、
  Windows は `*.vlb` のファイル）。存在しない・2 つ以上ある・フォルダかファイルかが異なる場合は失敗とします（Vectorworks が
  読み込めない形をインストールしない）。名前は記録に残し、`uninstall` の安全弁に使用します。
- zip の内容は、そのまま `<Plug-Ins>/<name>/` に配置します（ファイル名を列挙しない）。展開時には権限
  （実行ビット）を保持します。ファイルの時刻は zip の項目のものに戻さず、展開した時刻のままにします（構築は
  OS の一時フォルダの下で行うので、古い時刻を付けると、置換の前に OS の整理で削除されうるため。
  [インストール「作業領域」](plugin/install-and-update.md#作業領域)）。
- **失敗とするもの**: シンボリックリンク・絶対パスや `..` を含む項目（展開先の外へ出る）・`\` を
  区切りに使用した項目（区切りは `/` に限る。Windows PowerShell 5.1 の `Compress-Archive` が生成する形）・
  512 MiB を超える zip（終わらない本文で `<Plug-Ins>` と同じドライブを埋めないため。応答の `Content-Length` で
  大きさが判明すれば、取得する前に拒否する）・展開すると合計で 2 GiB を
  超える zip（小さな zip が大きく展開されて同じドライブを埋めないため。展開する前に、項目に記述された大きさの
  合計で拒否する）・項目が 100000 を超える zip（空のファイル・フォルダの多い小さな zip が、大きさの上限に掛からずに
  ファイルを作成し続けないため）。`./` で始まる項目
  （`zip -r x.zip ./` が生成する形）は、`./` を除いた名前として扱います。

## フック

**プラグインのフォルダの外に何かを配置するプラグインは、その配置方法と後処理の方法をフックに記述します。**
本プラグインは、PATH をフックで設定します（CLI とスプールはフォルダ内にある。[インストール「`cli` のフック」](plugin/install-and-update.md#cli-のフック)）。

- **フックは、Vectorworks の承認より前に、利用者の権限で実行されます。** プラグインのコードは、
  Vectorworks の「開発元不明のプラグイン」のダイアログで有効にした後でしか実行されませんが、フックは
  `install` の中で直ちに実行され、この同意を経ません。**レジストリを参照することは、そのレジストリが指す
  提供側のフックを実行することに同意することです。** 既定のレジストリの項目は、本リポジトリの
  レビューを経たもののみですが、**レビューは項目（名前と配置場所の規則）を掲載するときのみで、その後の
  リリースのマニフェストやフックには及びません。** 提供側は後のリリースでフックを自由に変更でき、
  `@latest` をインストールする利用者は、本リポジトリの誰も確認していないフックを実行します。既定のレジストリに
  掲載することは、その提供側を信頼すると決定したという意味です。`--registry` で追加するレジストリを信頼
  できるかは、呼び出し元が判断します。
- sha256 は、取得した zip がマニフェストに記述されたものと同一であること（途中で破損していない・すり替えられて
  いない）を検証するのみです。マニフェストを記述する提供側そのものを信頼できるかの裏付けにはなりません。
- フックのコードは zip の中に限ります（下記「記法」）。マニフェストに直接コマンドを記述できないので、
  実行されるのは sha256 で照合した zip の内容のみです。
- **定められた時点でのみ動作します。** `install` と `uninstall` の中で、**ロックを保持している Vectorworks が
  存在しないときのみ**実行されます（常駐の中で勝手に動作する処理にはならない。[設計「本番環境で常駐させる前提（安全性）」](design.md#本番環境で常駐させる前提安全性)）。
  ロックを保持していない Vectorworks（`cli` がインストールされていない・無効・起動の途中・2 つ目の起動）は判別
  できないので、**Vectorworks が停止していることの保証にはなりません**（[インストール「処理の流れ」](plugin/install-and-update.md#処理の流れ)）。
  フックは、Vectorworks が動作していても不具合が生じないように記述します。

### 記法

- 引数の配列で記述し、シェルを経由しません。
- 1 つ目は次のいずれかです。PATH からは検索しません。

  | 1 つ目 | 実行されるもの | 2 つ目 |
  | --- | --- | --- |
  | `sh` | `/bin/sh`（mac） | **zip 内のスクリプトの相対パス**（必須） |
  | `powershell` | System32（`FOLDERID_System`。環境変数 `SystemRoot` は読み取らない）の `WindowsPowerShell\v1.0\powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File`（Windows。Windows PowerShell 5.1） | **zip 内の `.ps1` のスクリプトの相対パス**（必須。`-File` は他の拡張子を拒否するので、他は読み込み時に拒否する） |
  | zip 内の相対パス | その実行ファイル | — |

- zip 内の相対パスは、展開したフォルダ内に実在するファイルでなければ失敗とします（絶対パス・
  `..`・`-` で始まるもの（`sh -c` のような指定）は拒否する）。1 つ目に記述したもの（インタプリタを経由しないもの）は、
  mac では zip 内で実行の権限を付与しておき、Windows では拡張子を `.exe`・`.com`・`.cmd`・`.bat` にします（そうで
  なければ置換の前に失敗とする。Windows は権限ではなく拡張子で実行方法を決定する。`PATHEXT` は読み取らない）。それより後ろの引数は、そのまま渡す文字列です。
- **管理された Windows では、`powershell` のフックが実行されないことがあります。** グループポリシー
  （MachinePolicy / UserPolicy）で実行ポリシーを `AllSigned` にした PC では `-ExecutionPolicy Bypass` が
  効かず、AppLocker / WDAC による Constrained Language Mode では `Add-Type` も停止します。そうした PC
  では `powershell` のフックを持つプラグイン（`cli` を含む）はインストールできません（`install` はフックの失敗
  としてフォルダを元に戻す）。対応はしません。

- 作業ディレクトリはプラグインのフォルダ（`<Plug-Ins>/<name>/`）です。標準入力は閉じて渡し、
  標準エラーは CLI の標準エラーへそのまま流します。
- **標準出力は、空か、UTF-8 で記述した JSON のオブジェクト 1 つ**とします。`install` / `uninstall` の出力の
  `hook` にそのまま掲載されます。それ以外（不正な UTF-8・2 つ以上の値・JSON でない行）を出力した場合は、
  終了コードが 0 でもフックの失敗として扱います（先頭の BOM と前後の空白は許容する）。標準出力は 1 MiB
  （レジストリとマニフェストと同じ上限）までのみを蓄積し、超えた場合はフックを最後まで実行させてから失敗とします。
  - Windows PowerShell 5.1 は、リダイレクトされた標準出力を OEM のコードページ（日本語の Windows なら
    CP932）で書き出します。`powershell` のフックは最初に `[Console]::OutputEncoding = [Text.UTF8Encoding]::new($false)`
    とし、JSON は `[Console]::Out.Write(...)` で 1 度だけ書き出します。
  - パイプラインに残った値（`New-Item`・`Add-Type` などの戻り値）も標準出力に出力されるので、`| Out-Null` か
    `[void]` で破棄します。進捗などは標準エラーへ書き出します。
- 時間の上限は設けません（CLI は待機の上限を定めない。停止するのは呼び出し元）。但し、フックが終了した後に、
  フックが残した子プロセス（`&` で起動したものなど）が標準出力・標準エラーを保持し続ける場合は、5 秒で待機を
  中止してパイプを閉じます（フックの結果はそのまま使用し、その旨を標準エラーに示す）。子プロセスに出力を継承
  させたい場合は、出力先をファイルへ変更します。

### 実行の時機

| フック | 時機 | 失敗した（0 以外で終了した・標準出力が JSON でない）場合 |
| --- | --- | --- |
| `install` | プラグインのフォルダを置換した後、後処理の前。初回のインストール時も更新時も。**インストール済みのものと同一のタグの場合は、zip を取得せず、置換もせずに、記録に複製したフックをインストール済みのフォルダで実行する**（フォルダの外に配置したものを再配置するため） | フォルダを元に戻して失敗で終了する（同一のタグの場合は、フォルダは変更していないのでそのまま）。フックがフォルダの外で変更したものは CLI では元に戻せない |
| `uninstall` | フォルダを `<Work>/old/<name>/` へ移動した後、削除する前。**インストール済みの版の**フック（記録に複製したもの）を、移動先のフォルダで実行する（`VW2026_HOOK_PLUGIN_DIR` も移動先。元の場所は `VW2026_HOOK_INSTALL_DIR`） | フォルダを `<Plug-Ins>/<name>/` へ戻し、何も削除せずに失敗で終了する |

- **フックは、何度実行しても同じ結果になるように記述します**（失敗の後に再実行しても、
  同一のタグの `install` で再実行しても破損しないため）。
- **`uninstall` のフックは、外部のものを削除し始めた後は失敗としません。** 失敗とすると CLI がフォルダを
  元に戻すので、外部のもののみが削除された状態になります。検証できることは削除する前に検証して失敗とし、削除し始めた
  後に削除できなかったものは標準出力の JSON に記載して 0 で終了します。
- **更新時に古い版の `uninstall` は実行しません。** 新しい版の `install` に前のタグを渡すので、
  前の版が配置したものの移行は新しい版が担当します（削除してから再配置すると、その間 CLI が
  存在しなくなるなど、後処理と再配置の間に空白が生じるため）。
- **古い版へ戻す場合**（`@<古いタグ>`）も同様で、古い版の `install` は新しい版が外部に配置したものを
  関知しません。そのため、**フックがフォルダの外に配置するものの名前と場所は、版をまたいで変更しない**
  ようにします（どの版の `uninstall` でも後処理できるように）。変更した場合、戻した後に新しい版の
  配置したものが残存しうることは、提供側の責任として受け入れます。

### フックに渡す環境変数

| 変数 | 内容 |
| --- | --- |
| `VW2026_HOOK_NAME` | 名前 |
| `VW2026_HOOK_TAG` | `install` はインストールするタグ、`uninstall` はインストール済みのタグ |
| `VW2026_HOOK_PREVIOUS_TAG` | `install` の場合、前にインストールされていたタグ（初回のインストールでは空。同一のタグの `install` ではインストール済みのタグ）。但し、インストール済みの版のフックが通らないまま残された版（フックの間に Vectorworks が起動した。記録の `hook_pending`）の後は、`<Work>/old/<name>/` に残存する前の版のタグ、無ければ空（フックが前の版から移行する処理を省略しないため。同一のタグで終える回も、別のタグへ更新する回も同様） |
| `VW2026_HOOK_TARGET` | ターゲット |
| `VW2026_HOOK_PLUGIN_DIR` | 現在プラグインのファイルがあるフォルダ（作業ディレクトリと同一）。`install` は `<Plug-Ins>/<name>/`、`uninstall` は移動先の `<Work>/old/<name>/` |
| `VW2026_HOOK_INSTALL_DIR` | プラグインがインストールされる・インストールされていたフォルダ（`<Plug-Ins>/<name>/`）。`install` では `VW2026_HOOK_PLUGIN_DIR` と同一。`uninstall` で、フォルダ内を指すもの（PATH など）を後処理するために使用する |

- **`vw2026` は、フックがフォルダの外に使用できる場所を用意しません**（`vw2026` の永続領域を持たない。
  [インストール「作業領域」](plugin/install-and-update.md#作業領域)）。フォルダの外に配置したもの（PATH など）を
  後処理するのは、提供側の `uninstall` のフックの責任です。必要とするプラグインが現れた場合は、場所と後処理の方法を
  定めて追加します（環境変数の追加は互換性のある変更）。
- `VW2026_HOOK_` で始まる名前が CLI の指定の環境変数（`CLAUDE.md`「Go」）と重複しないように、
  `hook` という名前のコマンドは作成しません。
- **2025 の CLI（`vw2025`）は同じ変数を `VW2025_HOOK_*` で渡します**（[版](plugin/editions.md)）。いずれの CLI も、
  呼び出し元の環境にあるどの版の `VW<4 桁>_HOOK_*` も渡さず、自身の版の名前のみを渡します。2025 と 2026 の両方に
  インストールされるプラグインのフックは、渡された名前で版を判別できます。マニフェスト（`vw2025.json`）と記録
  （`vw2025-install.json`）の記法は 2026 と同一です。

## インストールの記録

インストールしたプラグインのフォルダに `vw2026-install.json` を配置します（`<Plug-Ins>/<name>/vw2026-install.json`）。

```json
{
  "record_version": 1,
  "name": "cli",
  "registry": "default",
  "tag": "0.0.0-a1b2c3d",
  "target": "macos-arm64",
  "module": "cli.vwlibrary",
  "hooks": { "install": ["sh", "hooks/install.sh"], "uninstall": ["sh", "hooks/uninstall.sh"] }
}
```

| 項目 | 使用箇所 |
| --- | --- |
| `name` | `uninstall` の安全弁（フォルダ名と一致すること） |
| `registry` | 同一の名前のフォルダが別の出所のものでないかを検証する。既定のレジストリは `default`、それ以外は `--registry` に渡した URL をそのまま（大文字と小文字・`%XX` も含めて）残す。**比較するのは、この文字列同士のみ**です。同一のファイルを別の記法（`%XX` の記法・UNC と割り当てたドライブ・シンボリックリンク・名前の変わったファイル共有）で指すと別の出所とみなして拒否するので、利用者は毎回同じ記法で渡します |
| `tag`・`target` | 新しいかの判定（両方が一致すれば zip を取得せず、フックのみを実行して `up_to_date`）。`target` も比較するのは、同一のタグでも別のターゲットの資産は別物であるため |
| `module` | `uninstall` の安全弁（フォルダ内に実在すること） |
| `hooks.install` | 同一のタグの `install` で実行するフック（インストール済みの版のもの。マニフェストを再取得しない） |
| `hooks.uninstall` | `uninstall` で実行するフック（インストール済みの版のもの） |
| `hook_pending` | インストール済みの版の `install` のフックがまだ通っていない（構築時に `true` を書き込み、フックが通ったら除去する。フックの間に Vectorworks が起動して新しい版を残置した場合も、フックの途中で停止した場合も残る。無ければ通っている）。前のタグ（`VW2026_HOOK_PREVIOUS_TAG`）はこれで決定する（`<Work>/old/<name>/` の残り方から推測しない）。これがある間の `install` と `--check` の扱いは[インストール「置換の手順」](plugin/install-and-update.md#置換の手順) |

- **記録はプラグインのフォルダ内にのみ配置します。** 別の場所に記録ファイルを持たず、インストール先の `<Plug-Ins>`
  の場所も記録しません（インストールされた `vw2026` は自身の実行ファイルの場所から導出する）（[設計「決定事項」](design.md#決定事項)）。
- 記録を書き換える場合（`hook_pending` を除去する場合）は、隣に書き込んでから名前の変更で置換します（書き込みの途中で停止しても
  読み取れない記録を残さない。隣の名前は回ごとに異なる `vw2026-install.json.new-<時刻>` で、書き込めない・置換できない
  場合は、この回が書き込んだそれを削除する）。読み取った項目はそのまま書き戻し、この CLI の知らない項目も欠落させません。
- 記録は構築用の場所で zip の内容と共に配置し、フォルダと共に置換します（置換の途中で
  失敗して元に戻すと、記録も前のものに戻る）。
- **互換性**: 冒頭の規則の通り、未知の項目は無視し、`record_version` は古い CLI が読み取ると誤る変更の
  場合のみ上げます（後の CLI が書き込んだ記録を、`cli@<古いタグ>` で戻した古い CLI も読み取れるように）。
  `record_version` を上げたビルドより前へ戻すには、新しい CLI で `uninstall` してから、古いタグの
  初回スクリプトでインストールします。

## 提供側への要件

自動でインストールできるのは、次を全て満たすプラグインのみです。満たさないプラグインは、利用者が手動で
インストールします（`vw2026` は手動でインストールしたフォルダに触れない）。

- **レジストリに掲載されていること**（既定のレジストリなら本リポジトリへの PR。又は利用者が渡す
  レジストリ）。
- **規則が指す場所にマニフェストがあり、資産は絶対参照で、sha256 が記述されていること。**
- **タグを再利用しないこと。** 最新を指す名前が必要なら、配置場所で用意する（GitHub のリリース
  なら `releases/latest/download/vw2026.json` が下書きでもプレリリースでもない最新を指す。それ以外の
  名前は、提供側が書き換えるファイルで用意する）。
- **フォルダ名に依存しないこと。** フォルダ名はレジストリの名前で決まり、提供側は選択できません。
  自身のファイルは、モジュール自身の場所からの相対で見つけます。
- **保持したいものをプラグインのフォルダに書き込まないこと。** 更新でフォルダごと置換され、`uninstall` で
  フォルダごと削除されます。Vectorworks の動作中のみ必要なもの（`cli` のスプールなど）は配置して差し支えありません
  （更新と `uninstall` は Vectorworks が停止している間にしか行わない）。保持したいもの（設定など）は
  フォルダの外の提供側が定めた場所に配置し、`uninstall` のフックで後処理します。
- **モジュールのファイル名を版をまたいで変更しないこと。** Vectorworks は署名の無いプラグインの
  「有効化」をモジュールのフルパスで記憶するので、名前が変わると利用者は有効化をやり直すことに
  なります（[Findings「Plug-in Modules」](https://github.com/min-nano/vectorworks-developer-sdk-reference/blob/main/Findings/Plug-in%20Modules.md)の「開発元不明のプラグイン」のダイアログ）。
- **独自のインストーラ・アップデータと併用しないこと。** `vw2026` でインストールしたものは `vw2026` で更新します。

**同一のプラグインを二重にインストールしないのは利用者の責任です。** 同一のプラグインが 2 つ存在する場合に Vectorworks が
何をもって衝突とみなすかは、SDK リファレンスで確認されていません（`Findings/` に記載が無い）。
衝突しうる値（ユニバーサル名・拡張機能の UUID・リソースの識別子）はいずれもコードが登録時に渡すもので、
外部から読み取れる識別子もありません。確認されていない挙動に依存する判定を作らないため、`vw2026` は
ファイル名などで中途半端に判別することをしません（判定を作らないので、この調査は実装を待機させない。
[SDK の調査](sdk-research.md)）。防止するのは、同一の名前のフォルダへの
上書きのみです（[インストール「インストール先のフォルダ」](plugin/install-and-update.md#インストール先のフォルダ)）。
