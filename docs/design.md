# 設計

## 目的

**Vectorworks を外部から機械的に操作するための受け口を、独立したプラグインとして提供します。**

- プラグイン（C++・VW SDK）が Vectorworks の中で**本番でも常駐する**ブリッジを持つ
- 同梱の CLI（`vw2026`）・ほかのプラグイン・任意のスクリプトが、そのブリッジ越しに
  Vectorworks を操作する
- はじめは図面を読む道具だけ。**将来は図面の変更も CLI 越しに機械的に行えるようにする**
  ための布石

## 決めたこと

| 項目 | 決定 | 理由・補足 |
| --- | --- | --- |
| MCP | **このリポジトリには含めない**（別のプロジェクトの責任） | MCP は CLI を呼び、セッションの見分け・占有などの安全策を担うラッパーになる |
| CLI の性格 | **プリミティブ**。指示されたとおりに 1 回動く | 占有・セッション間のロック・再試行は持たない（下記） |
| 他のプラグインの道具 | **このプラグインが唯一の受け口**になり、ほかのプラグインの機能を**ユニバーサル名で呼び出す** | 呼び出しの手段は SDK の調査待ち（下記） |
| 殻と本体 | **最初から分ける**（ホットリロード。更新は CLI が行う） | 常駐するプラグインなので、更新のたびの再起動を避ける |
| CLI の言語 | **Go** | 単一の実行ファイルで、ランタイム不要。mac（arm64/amd64）と Windows を 1 つの CI から作れる |
| 構造設計支援のブリッジ | **当面は並存**。移行はあとで決める | スプールの名前が違うので混ざらない（[作法](protocol.md#元の作法との違い)） |
| 名前 | プラグイン `cli`（開発版 `cli_dev`）・コマンド `vw2026` | コマンド名はプラグインのインストール先の Vectorworks の版。版ごとにプラグインを入れるので、版の違う Vectorworks が同居してもコマンドが衝突しない。配布後に変えるとスプールの名前・リンク・ユニバーサル名が変わる |

## 構成

```
   vw2026 / ほかのプログラム
          │ <id>.req.json を置く／<id>.res.json を待つ
          ▼
   スプール（<temp>/vectorworks2026-cli-bridge/。0700）
          ▲
          │ 取り出す／応答する
          │
   ┌──────┴───────────── Vectorworks ─────────────────────────┐
   │  殻（.vwlibrary）… 起動時に 1 度だけ読まれる                 │
   │   ・OS タイマー（受け付けを呼ぶ）・本体の読み込み             │
   │   ・拡張機能は登録しない（更新は vw2026 update が行う）        │
   │          │ 読み込む／タイマーから呼ぶ                         │
   │          ▼                                                 │
   │  本体（.vwpayload）… いつでも降ろして読み直せる               │
   │   ・ブリッジ・道具（読む／書く）                              │
   │          │ ユニバーサル名で呼ぶ（手段は SDK の調査待ち）       │
   │          ▼                                                 │
   │  ほかのプラグイン（構造設計支援など）                          │
   └────────────────────────────────────────────────────────────┘
```

### プラグイン（殻と本体）

構造設計支援プラグインで実機で確かめた作りを引き継ぎます（あちらの `CLAUDE.md`
「殻と本体」・`docs/development/mcp-bridge.md`・M41「受け付けを殻の OS タイマーへ」）。

- **殻**: OS タイマー・本体の読み込み・Vectorworks の終了の依頼。**実処理は置かない**
  （直すたびに再起動を強いる）。メニューなどの拡張機能は登録しない。
- **更新は CLI（`vw2026 update`）が行う。** 殻が変わる更新は、Vectorworks の終了を待って
  入れ替える（[更新](plugin/install-and-update.md#更新vw2026-update)）。
- **本体**: ブリッジ（スプールの受け付け）と道具のすべて。いつでも降ろして読み直せる。
- 境界は C の ABI 1 つ。例外・C++ のオブジェクトを越えて渡さない。境界を越えた構造体は
  受け取った側が複製する。本体のコードがスタックに載っている間はアンロードしない。
- **受け付けは殻の OS タイマーが 1 回ずつ呼びます。** 本体の中にループを書きません
  （図面が操作できなくなる）。undo の記録が開いている間の呼び出しは見送ります。
- **SDK 呼び出しはメインスレッドからだけ**行います。受け付け用のスレッドは持ちません
  （本体をアンロードした瞬間にそのスレッドのコードが消える）。

### なぜファイルで受け渡すのか

ソケットや名前付きパイプでも作れますが、次の理由でファイルにしています。

- 実行はどのみちタイマーの 1 回の中なので、通り道を変えても速くならない
- **本体の入れ替え・Vectorworks の再起動をまたいでも、要求と応答が残る**
  （ソケットは接続が切れるので、再接続と再送の作法が別に要る）
- macOS のファイアウォールの確認が出ない。Winsock と BSD ソケットで分岐しない

## CLI はプリミティブに保つ

`vw2026` は**指示されたとおりに 1 回動くだけ**の入口です。

- 持つもの: スプールの探索・要求を置いて応答を待つ・Vectorworks の起動・ブリッジが
  動き出す（止まる）のを待つ・**プラグインの更新**（`vw2026 update`。殻が変わるときは
  Vectorworks の終了を待って入れ替える）
- 持たないもの: **占有・セッション間のロック**・再試行・道具ごとの解釈（引数の検証は
  プラグイン側の仕事）
- 出力は標準出力へ JSON 1 行。成否は終了コード（[CLI](cli.md)）

占有を持たないので、2 つのプロセスが同時に書く道具を呼べば、図面への操作は送った順に
混ざります（受け渡し自体は壊れない）。**安全にセッションから使う責任はラッパー（MCP など）に
あります。**

## 他のプラグインの道具

このプラグインを**唯一の受け口**にし、ほかのプラグイン（構造設計支援など）が提供する機能を
**ユニバーサル名で呼び出す**形を目指します。ほかのプラグインはこのプラグインを知らずに
済み、このプラグインは名前で引くだけになります。CLI から見た道具の名前は
`<提供者>.<名前>` にする予定です。

**呼び出しの手段は、SDK でできることが分かってから決めます**（リポジトリの決めごと
「SDK の調査はリファレンス側で行う」）。調査は
[SDK リファレンス #217](https://github.com/min-nano/vectorworks-developer-sdk-reference/issues/217)
で、候補と調べることは [SDK の調査](sdk-research.md) にまとめています。それまでは、この
プラグイン自身の道具だけを提供します。

## 本番で常駐させる前提（安全）

開発版だけの道具だった元のブリッジと違い、**利用者の Vectorworks で常に受け付けます。**
前提は次のとおりで、崩す変更をするならこの判断をやり直します。

- **相手は同じ計算機の同じ利用者のプロセスだけ**（スプールは 0700。持ち主と権限を検査）。
  その利用者の権限で動くプログラムは、どのみち利用者のファイルを読み書きできる。
- **頼まれたときにしか動かない。** 勝手に回る処理（定期的な取り込みなど）は持たない。
- **図面に書き込む道具は undo の作法を必ず通す**（[SDK リファレンス「Undo」](https://github.com/min-nano/vectorworks-developer-sdk-reference/blob/main/Findings/Undo.md)）。
  人が図面を操作している最中にも要求は届くので、人の操作と undo の記録が混ざらないかを
  先に確かめる。
- **利用者の図面を保存せずに閉じる・消す道具は持たない。**
- **受け付けを止める手段は持たない**（止めたければアンインストールする）。代わりに、
  Vectorworks の処理中（undo の記録が開いている間など）はその回の受け付けを見送る
  （[構成「受け付けを止めない・処理中は見送る」](plugin/architecture.md#受け付けを止めない処理中は見送る)）。

## 配布と PATH

- 配布 zip の直下に、殻・本体・インストーラ・アンインストーラ・`bin/vw2026`（Windows は
  `bin\vw2026.exe`）を置きます。インストーラは「zip の直下の `bin/` は CLI の場所へ、それ以外は
  そのままプラグインのフォルダへ置く」。
- **CLI はプラグインのフォルダの外に置きます**（mac `~/Library/Application Support/vectorworks2026-cli/bin/`、
  Windows `%LOCALAPPDATA%\vectorworks2026-cli\bin\`）。Windows では開いているファイルを含む
  フォルダの名前を変えられないので、CLI がプラグインのフォルダの中で動いていると、更新で
  プラグインのフォルダを付け替えられなくなるためです
  （[インストールと更新「置き場所」](plugin/install-and-update.md#置き場所)）。
- **PATH はインストーラが通します**（プラグインの起動時には何もしない）。
  - macOS: `~/.local/bin/vw2026` → `<CLI の場所>/bin/vw2026` のシンボリックリンク
    （sudo 不要）。`~/.local/bin` が PATH に無ければ、追加の方法を表示するだけでシェルの
    設定ファイルは書き換えない。
  - Windows: 利用者の PATH に `<CLI の場所>\bin` を追加する。
- アンインストーラは**自分のフォルダを指すリンク・PATH の項目だけ**を取り除きます。
- macOS では、インストーラが隔離属性の解除とアドホック署名を `bin/` にもかけます。
