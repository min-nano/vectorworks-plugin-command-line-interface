# 実機での検証方法

プラグインとスクリプトの変更の内、実機でしか検証できないものの検証方法です。マージの条件
（利用者が実機で「確認できた」と言うまでマージしない）は `CLAUDE.md`「作業の進行」にあります。PR には、
検証方法と、検証の結果・確認できなかった項目を記述します。

## 検証事項

実機の確認は、**ツールの結果（応答・図面への作用・描画）が想定どおりか**を検証するためのものです。
ビルドが通ることと単体テスト・通信規則のフィクスチャの照合は CI が保証します（CI は main と統合した
マージ用のコミットで実行される）。そのため、PR のブランチを main に追従させることは要求しません。
プレリリースは head でビルドするので（[ビルドとリリース「リリースの構成」](build-and-release.md#リリースの構成)）、
ブランチの作成後の main の変更が**ツールの振る舞い・描画に影響しうる**と判断した場合のみ、
ブランチに main を取り込んでから検証します。

実機では `vw2026` で検証します。ローカルの Claude Code セッションから `vw2026` を呼び出し、結果の JSON を
読み取ります。図面に何かが起きたかは人に確認を依頼します。

## PR のビルドのインストール

PR は、その PR のプレリリースをインストールして検証します（同じ名前のプラグインとして置換される）。タグは
push ごとに変わるので、PR の最新の push のタグを使用します。タグは構築せずに、その PR のプレリリースの名前から
読み取ります（通常は `dev-<slug>-<PR 番号>-<短い sha>`、slug が空になるブランチ名なら `dev-<PR 番号>-<短い sha>`。
形式は[名前と識別子](identifiers.md)の「リリースのタグ」）。

- **インストール**: Vectorworks を終了してから `vw2026 install cli@<その PR のタグ>`（`quit` で終了させてもよい。
  終了から再起動までの組み合わせは[インストール「処理の流れ」](install-and-update.md#処理の流れ)）。インストールされたことは、
  再起動後の `vw2026 call ping` の `version`（PR の head の短い sha）と `branch` で確認します。
- **復元**: `vw2026 install cli@latest`（main の最新）。
- **`cli` が未導入の計算機と、`install`・初回スクリプトそのものを変更する PR**: その PR のプレリリースの
  初回スクリプト（`releases/download/<その PR のタグ>/get-vw2026.sh` / `.ps1`）でインストールします（スクリプトは、
  取得したリリースのタグをインストールする。[インストール「初回スクリプト」](install-and-update.md#初回スクリプトget-vw2026sh--ps1)）。
- **zip を展開しただけの `vw2026` では検証しません。** `vw2026` は自身の実行ファイルの場所からスプールを
  算出するので、フォルダの外の CLI はインストール済みの `cli` のスプールを参照しません
  （[通信規則「スプールの場所」](../protocol.md#スプールの場所)）。
- **zip を手動で取得する場合は `curl -L` か `gh release download` を使用します。** ブラウザで取得すると隔離属性（mac）や
  Web からの標識（Windows）が付き、アドホック署名のモジュールと CLI が阻止されて、プラグインと無関係の理由で
  検証が失敗します（`install` はこれらが付かない前提。[インストール「前提」](install-and-update.md#前提)）。
- **種類 `write`・`app` のツール（`save`・`close`・`quit` など）は、`session start` のセッション ID を `--session` に付けて
  呼び出し、最後に `session end` します。** セッション ID が無いと終了コード 23 で拒否されます（占有の前後なら `no_session`、
  他が占有している間なら `occupied`）。`VW2026_SESSION` を環境に設定していると、セッション ID なしのつもりの呼び出しにも
  セッション ID が付与されるので、セッション ID なしの振る舞いを確認する場合は除外します。

## 「開発元不明のプラグイン」のダイアログ

mac でも Windows でも、起動の途中に「開発元不明のプラグイン」のダイアログが表示されることがあります
（無効のものがあれば毎回、全て有効なら約 24 時間おき。[構成「拡張機能の非登録」](architecture.md#拡張機能の非登録)）。

- `cli` が「無効」と表示されていれば、`cli` を選択して「有効化」し、Vectorworks を再起動します。「有効」と
  表示されていれば `cli` は読み込まれています。
- ダイアログの最中に確認済みなのは図面を開く・作成する・書き込む・保存する・閉じることのみなので、実機の確認は
  ダイアログを「続ける」で閉じてから行います。

## Windows

- 終了コードはプロセスの終了前にハンドルを開いて読み取り、異常終了の箇所は LocalDumps のダンプで確認します
  （[Windows の実機での検証方法](windows-measurements.md)「検証方法」）。
- **検証できるのは描画を伴わない範囲までです。** 用意できる Windows の環境（仮想環境）は DirectX なしでしか
  Vectorworks を起動できないためです（利用者の判断。SDK リファレンスも同じ理由で Windows の測定の一部を
  保留している。[#316](https://github.com/min-nano/vectorworks-developer-sdk-reference/issues/316)）。描画を伴う
  項目（図面の表示を目視で比較するもの・描画の途中で起きることなど）は mac のみで検証し、Windows で
  確認しなかった項目は PR に記述します。
- 終了を待機する場合は 30 秒以上待機します。Windows は終了の呼び出しが戻ってからプロセスが 28〜30 秒存続して
  ロックを保持するためです（[Findings「Timers and Notifications」](https://github.com/min-nano/vectorworks-developer-sdk-reference/blob/main/Findings/Timers%20and%20Notifications.md) の 4 の 9）。
- UNC の保存先は、事前に作成した共有（`\\localhost\<共有>\…`）で検証します。管理共有（`C$`）は昇格して
  いない Vectorworks では拒否され、プラグインの不具合と判別できません。

## 確認項目

関連するツール・手順を変更した場合に、該当する項目を再実施します。掲載するのは実機でしか確認できないもののみで、
引数の検査の細目など、無 SDK のテストが検証するものは掲載しません。ツールを追加したら、そのツールの項目をここに追加します。

### 起動と `ping`（全ての変更）

- `launch` の後 `status` が `running:true` になり、`call ping` の `version` が PR の head の短い sha、`branch` が
  その PR のブランチになる。`vw2026 tools` にツールが列挙される。
- `launch` の直後から `status` を短い間隔で繰り返し、`running:true` になった直後（起動画面の間）の `call ping` が
  異常終了せずに応答する。
- 図面を 1 枚も開いていない場合の `ping` が、`document_open` が偽・`current_layer` が `null` で応答する。

### 読み取りツール（mac と Windows）

- レイヤ・クラス・図形の数と名前を定めた検証用の図面（スクリプトで作成する）に対して、結果が画面の表示と一致する。
  - レイヤとクラスの構成・縮尺はオーガナイザと比較する（並び順はオーガナイザと異なるので、
    [ツール「読み取りツール」](tools.md#読み取りツールlayersclasseslayer_objectsobject_counts)に記述した向きで比較する）。
  - 数は、レイヤごとに「全てを選択」したときの情報パレットの「N 図形」と比較する（オーガナイザに数の列は無い）。
- 参照で取り込まれたレイヤが、参照の方法の 2 通りとも[ツール「`layers`」](tools.md#layers)の表の通りに返る。シートレイヤの
  ビューポートが検証用の図面の通りに返る。
- `layer_objects` の `limit`・`offset`・`type` が記述の通りに機能し、存在しないレイヤは `invalid_args` で拒否される。
- 図面を 1 枚も開いていない場合、読み取りツールが `internal`（`no_document`）で失敗する。

### 占有

- 種類 `write`・`app` のツールをセッション ID なしで呼び出すと、何も起きずに終了コード 23 で拒否される（`session start` の前と
  `session end` の後は `no_session`、占有されている間は `occupied`）。
- Vectorworks の再起動後の古いセッション ID も `no_session` で拒否される。

### `documents`・`save`・`close`（mac と Windows）

- `documents` が開いている図面の一覧と一致する。
- `save` で無題の図面を一時フォルダへ保存できる。前面の図面とそのカレントレイヤが保存の前後で変わらず、結果の
  `path` をそのまま `close` の `document` に渡せる。
- 保存済みの図面も新しい `to` へ保存でき（図面のパスが `to` へ移り、元のファイルはハッシュが変わらない）、同一の図面を
  別の新しい `to` へ再度保存できる。
- 開いている図面のパスを `to` に渡すと `internal`（`to_is_open`）で拒否され、警告のダイアログが表示されない。**大文字と
  小文字のみが異なる `to` でも `to_is_open` になる**（本物の比較方法が渡っていることの検証。mac では NFC と NFD のみが
  異なる `to` も確認する）。
- 開いていない既存のファイルを `to` に渡すと `internal`（`file_exists`）、存在しないフォルダの下は `parent_missing`、
  `.vwx` でない `to` と `.`・`..` を含む `to` は `invalid_args` で拒否される。
- `close` は、どの図面でも保存の確認を表示せずに閉じる（保存した図面・保存していない無題の図面・変更のある保存済みの
  図面。変更は破棄され、ファイルは変わらない）。閉じた後の一覧に図面が残らない。
- 別々のフォルダにある同じ名前の旧版のファイルを 2 つ開き、`documents` の `path` が重複する場合に `save`・`close` が
  `document_ambiguous` で拒否する。読み取り専用のファイルを開いたコピーも保存の確認を表示せずに閉じる（旧版のファイルは、mac の
  「ファイル > 取り出す」で旧版の形式にして作成する）。
- 図面を 1 枚も開いていない場合、セッション ID を付けた `save`・`close` が `internal`（`no_document`）で失敗する。

### `export_pdf`（mac）

- シートレイヤを 2 枚以上、`layers` の順と違う順で `sheets` に渡すと、その順に 1 枚 1 頁の PDF が `to` にでき、結果の
  `pages` が頁の数と一致する。書き出しの間にダイアログが表示されず、PDF の閲覧ソフトも開かない。
- 同じ計算機で同じシートをパブリッシュした PDF と見比べ、頁の大きさと描かれたものが同じである。
- 前面でない図面を指定しても書き出せ、前面の図面とそのカレントレイヤが書き出しの前後で変わらない。undo の履歴に
  段が増えない。
- 利用者の PDF の書き出しの設定（「PDF を開く」と範囲）が、書き出しの前後で変わらない（GUI の「PDF の取り出し」の
  ダイアログで見る）。
- 既にある `to` は `file_exists`、無いフォルダの下は `parent_missing`、デザインレイヤの名前・無い名前を含む `sheets` は
  `invalid_args` で拒否され、いずれもファイルができない（既にあるファイルは変わらない）。

### `save` の保存先（Windows）

`CLAUDE.md` の 7 が実機の確認に委ねている、CI の環境で再現できない場面です
（[保存先の検証](save-target.md)を変更した場合に再実施する）。

- UNC の `to`（事前に作成した共有 `\\localhost\<共有>\…`）へ保存できる。その図面を閉じてから、別の無題の図面で
  同じ UNC へ保存すると `file_exists` で拒否される（閉じずに渡すと `to_is_open`）。
- 存在しない共有（`\\localhost\<無い共有>\a.vwx`）は `parent_missing` で拒否される（「無い」の表の 67 を本物の呼び出しで
  検証する）。
- 存在しないサーバー（`\\<無いサーバー>\<共有>\a.vwx`。長い `--timeout` を付ける）は `to_check_failed` で拒否される
  （`os_error` は「無い」の表に無い番号で、通常は 53。ネットワークによって 1231 などにもなる）。
- `/` 区切りの `to`（`C:/…/a.vwx`）が `invalid_args` で拒否される（形式の規則が Windows のものになっていることの検証）。

### `quit`（mac と Windows）

- `launch` の後 `status` が動作中と応答した直後（ホーム画面の表示前）に `session start` と `call quit` を呼び出すと、
  ダイアログが表示されずに `internal`（`starting`）で拒否されて Vectorworks が起動を継続し、ホーム画面の表示後に再度呼び出すと
  停止する。
- 図面（無題と、保存済みの図面を変更したもの）を開いて `call quit` を呼び出すと、ダイアログが表示されずに `internal`
  （`documents_open`）で失敗して `detail` に一覧が載り、`call ping` が応答し、`session end` で占有が解除される。
- 図面を全て `close` してから `call quit` を呼び出すと、ダイアログが表示されずに `status` が停止中と応答する。
  **閉じる順序に依存しない**（2 枚を開き、先に開いた方を変更して、先に開いた方・後に開いた方の順に `close` しても、
  保存の確認が表示されずに停止する。同じ形の `close` の後に利用者がメニューの「終了」で終了しても確認が表示されない。
  [ツール「閉じた図面の後処理」](tools.md#閉じた図面の後処理)）。
- 更新の組み合わせ（`session start` → `call quit` → 停止を待機 → `install` → `launch` → 動作の開始を待機。
  [インストール「処理の流れ」](install-and-update.md#処理の流れ)）で、`call ping` の `version` が変わる。
- 利用者がメニューの「終了」で終了したときに、異常終了せずに終了する。

### インストールと初回スクリプト（mac と Windows）

- その PR のプレリリースの初回スクリプトを引数なしで実行すると、新しい端末で `vw2026 status` が動作し、起動して
  `call ping` の `version` が PR の head の短い sha になり、スプールが `<Plug-Ins>/cli/spool/` に作成されている。
- Vectorworks の動作中の `install cli@<同じタグ>` は、「Vectorworks が動作中」の終了コードで何も変更しない。
- Vectorworks の終了後の同じタグの `install` は `up_to_date` で終わる（zip を取得せず、フックのみが実行される）。
  `~/.local/bin/vw2026`（Windows は `Path` の項目）を手動で削除してから実行すると、元に戻る。
- PR に push して新しいタグが作成されたら、インストール済みの `vw2026` で `install cli@<新しいタグ>` を実行すると `installed` に
  なり（Windows では実行中の CLI が退避されて差し替えられる）、`vw2026 version` が新しい sha になる。差し替えた
  後の起動で、`cli` が「有効」のまま読み込まれる。
- 初回スクリプトに `--plugins-dir <場所>` を渡すと既定以外へインストールされ、そこにインストールされた `vw2026` は指定なしでその場所を
  使用する（インストールされた `vw2026` に `--plugins-dir` を渡すと使用方法の誤りで拒否する）。
- インストール済みの `vw2026` の `uninstall cli` は、何も変更せずに終了コード 2 で終わり、初回スクリプトに `uninstall` を渡す
  コマンドを示す。そのコマンドを実行すると、プラグインのフォルダ（CLI とスプールを含む）・リンクと PATH の項目のみが
  削除され、何も残らない。
- 記録の無い `<Plug-Ins>/cli/`（手動で配置したもの）には、`install` が拒否してインストールしない。
- 検証後、`install cli@latest` で main の版に戻り、`call ping` の `version` が main の sha になる。
