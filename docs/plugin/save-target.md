# `save` の保存先（`to`）の検証

ツール `save`（[ツール「図面を操作するツール」](tools.md#図面を操作するツールdocumentssaveclose)）は、保存を呼び出す前に保存先 `to` を
検証します。Vectorworks は保存先の形式を検証せずにその名前で保存し、成功と区別が付かないものがあり、保存先に
よっては人が押すまで制御を返さない警告を表示するためです（[SDK リファレンス #288](https://github.com/min-nano/vectorworks-developer-sdk-reference/issues/288)）。
本ページは、その検証の規則と理由の真実です。

| 検証 | 失敗 | 節 |
| --- | --- | --- |
| 形式 | `invalid_args` | [`to` の形式](#to-の形式) |
| 状態 | `internal`（`to_is_open` → `file_exists` → `parent_missing`。検証できなければ `to_check_failed`） | [状態の検証](#状態の検証)・[ネットワークの場所](#ネットワークの場所) |

`save` はいずれの検証も前面を切り替える前に行うので、拒否した場合に前面の図面は変わりません。

**`export_pdf` の書き出す先（`to`）も、本ページの規則で検証します**（[ツール「export_pdf」](tools.md#export_pdf)）。違いは次の 3 つで、
それ以外（形式の規則・`file_exists` → `parent_missing` の順・ネットワークの場所）は同じです。本ページの `.vwx` は、`export_pdf` では
`.pdf` と読み替えます。

- 拡張子は `.pdf` です（形式の規則の関数は拡張子を引数で受け取る）。
- `to_is_open` は返しません（開いている図面は `.vwx` なので、`.pdf` の `to` と一致しない）。
- 状態は、シートレイヤの名前を確かめるために前面を切り替えた後に検証します。拒否した場合も前面は元に戻ります。

## `to` の形式

**`to` の形式は、保存を呼び出す前に検証して `invalid_args` で拒否します。** プラグインはパスを書き換えず（正規化して
渡さず）、次のいずれかに該当する `to` を拒否します。

- **Windows では `/` を含む `to` を拒否します**（修正して渡さない）。Vectorworks に `/` 区切りのまま渡すと、別の名前で
  暗黙に保存されます（[Findings「Windows——測れた範囲」](https://github.com/min-nano/vectorworks-developer-sdk-reference/blob/main/Findings/Documents.md#windows測れた範囲288)。#288）。呼び出し元が `\` 区切りで渡します。
  プラグインはパスを書き換えないので、渡した文字列の通りに保存されます。
- 絶対パスでない・区切りで終わる（フォルダを指す）。**受理する絶対パスは、mac は `/` から始まるもの、Windows は
  `X:\`（ドライブ文字・`:`・`\`。ドライブ文字は ASCII の `A`〜`Z`・`a`〜`z` で、ロケールに依存する判定をしない）で始まる
  ものと、UNC（`\\<サーバー>\<共有>\…`）です。** UNC はサーバー・共有・その下の 1 段以上（ファイル名）を必要とします
  （`\\<サーバー>\<共有>\<名前>.vwx` が最小。`\\server\a.vwx` と `\\server\share` は拒否する）。Vectorworks は UNC へ
  保存でき、渡した文字列がそのまま図面のパスになります（実機では管理共有 `\\localhost\C$` への保存を確認した。事前に作成した共有への保存は確認していない。[Findings「保存先のパスの形」](https://github.com/min-nano/vectorworks-developer-sdk-reference/blob/main/Findings/Documents.md#保存先のパスの形unc相対-と-294)。#294）。
  Windows の他の形式——`\\?\`（保存されない）・`\\.\`（図面のパスにデバイスの名前空間が残る）・ドライブ相対の
  `C:a.vwx`・ルート相対の `\a.vwx`（保存されない）——は拒否します（いずれもダイアログは表示されない。#294）。
  UNC の綴りと別の綴りで同じファイルを指す場合の比較は、下記「[パスの一致の判定](#パスの一致の判定)」に記述します。
- `.`・`..` の段、空の段を含む（mac も Windows も）。空の段は、区切りが 2 つ以上連続する箇所で、先頭も含めて拒否します
  （mac の `//a.vwx`・`/x//a.vwx`、Windows の `C:\x\\a.vwx`。Windows の UNC の先頭の `\\` は丁度 2 つのみを除外し、3 つ目からは空の段として拒否する——
  `\\\server\share\a.vwx` も拒否する）。Vectorworks はこれらを字面で処理し（`..` と `//` を畳み、`.` を残す）、`x/./../a.vwx` は渡したパスと
  別のフォルダへ暗黙に保存されます。`.` の段を含むパスは図面のパスに残り、開いている図面との比較から外れます。
  `//` は同じフォルダへ畳まれますが、渡した文字列と図面のパスが食い違い、比較の方法が単純でなくなるので、同様に拒否します
  （#294）。
  **プラグインは正規化して渡さず、拒否します。** これは Findings の推奨（[「CLI の `save` への帰結（パスの形）」](https://github.com/min-nano/vectorworks-developer-sdk-reference/blob/main/Findings/Documents.md#cli-の-save-への帰結パスの形294):
  `to` は字面で正規化してから渡す）と異なる決定です。字面で畳むとシンボリックリンクを段に含むパスで OS の解決と齟齬が生じるので、
  正規化は呼び出し元（自身の OS でパスを解決できる）に委ねます。
- Windows では、途中の段（フォルダの名前）の末尾が `.` か空白のもの（`C:\x.\a.vwx`・`C:\x..\a.vwx`・`C:\x \a.vwx`）を含む。
  Vectorworks は文字列を修正せずに OS に渡すので、`x.\` は Win32 の正規化で `x\` に格納されるのに図面のパスは `x.\…` のまま残り、
  `.` の段と同様に開いている図面との比較から外れます。UNC ではサーバーの名前の段にも適用します（末尾に `.` の付いた完全修飾のホスト名 `\\fs.example.\share\a.vwx` も拒否する。
  `\\fs.\…` と `\\fs\…` が同じファイルを指して開いている図面との比較から外れるのを防止するため。呼び出し元は末尾の `.` を除去して渡す）。`x..\`・`x \` は実在する別のフォルダを指しえます
  （[Findings「途中の段の末尾が `.` か空白の保存先」](https://github.com/min-nano/vectorworks-developer-sdk-reference/blob/main/Findings/Documents.md#途中の段の末尾が--か空白の保存先windows299)。#299）。**正規化して渡さず、拒否します。**
- 拡張子が `.vwx` でない（大文字と小文字は区別しない）。Vectorworks は拡張子を追加せず、`.txt`・`.dwg` でも内容は
  Vectorworks の形式のまま、その名前で保存します。末尾が `.` の名前もここで拒否します（Windows は点を除いた
  ファイルを作成し、図面のパスと食い違う）。
- Windows では、先頭（ドライブ名の `X:`、UNC の `\\`）の後のいずれの段にも——UNC のサーバーと共有の段を含めて——`< > : " | ? *` を含む（`GSError` が 0 のまま `%3F` などに化けた名前で
  保存される）。
- Windows では、255 文字（UTF-16 の単位）を超える段か、全体が 260 文字（UTF-16 の単位。サロゲートペアは 2 つと数える）以上の `to`（段の上限はファイルシステムの名前の長さ。全体の境界は `MAX_PATH`）。SDK はこれを保存できないので、検証の前に拒否します
  （[Findings「Windows」](https://github.com/min-nano/vectorworks-developer-sdk-reference/blob/main/Findings/Documents.md#windows振る舞いは-mac-と同じ違うのはパスの比べ方と開ける図面は-8-枚まで)）。
- mac では、255 バイト（UTF-8）を超える段か、全体が 1024 バイト（`PATH_MAX`）以上の `to`。ファイルシステムの検証が
  `ENAMETOOLONG` で失敗し、`to_check_failed`（状態の失敗）に見えてしまうので、引数の誤りとして検証の前に拒否します。
- 制御文字（U+0000〜U+001F）を含む（mac も Windows も）。SDK の振る舞いは確認していないので、確認せずに拒否します。
  Windows の予約された名前（`CON.vwx` など）は、SDK が通常通りに保存したので拒否しません
  （[Findings「Windows——測れた範囲」](https://github.com/min-nano/vectorworks-developer-sdk-reference/blob/main/Findings/Documents.md#windows測れた範囲288)。`CON` 以外は確認していない）。

## 状態の検証

**`save` の状態の検証（`internal`）は、`to_is_open` → `file_exists` → `parent_missing` の順に行います**（OS の呼び出しが「無い」以外の理由で失敗すれば、その段階で `to_check_failed`。[ツール「共通の規則」](tools.md#共通の規則)の検証の順序の 4）。開いている図面と
一致する `to` は、そのフォルダが削除されていても `to_is_open` を返します。

**`to` に既存のファイルを渡しても保存できません**（SDK が `GSError` 50331649 を返し、何も起きない。
mac・Windows とも、いずれの形式で渡しても）。**保存先が別の図面で開いているファイルであれば、SDK が警告のダイアログを
表示し、人が OK を押すまで制御を返しません**（mac も Windows も、開いている図面のパスと文字列が完全に一致する場合のみ表示される）。
そこで、呼び出す前に次の順に検証して `internal` で拒否します。

1. `to` が開いている図面のパスと一致する（比較の方法は下記「[パスの一致の判定](#パスの一致の判定)」）。保存先が開いている図面であると
   示すため（`to_is_open`）、先に検証します。
2. `to` がディスクに存在する（ファイルシステムに問い合わせる）。大文字と小文字・8.3 の短い名前の違いは
   ファイルシステムが吸収するので、文字列の比較の方法に依らずに防止できます。

上書きする場合は、呼び出し元が先にファイルを削除します。**呼び出し元が機械的に区別できるよう、失敗の `detail` に
`reason` を付与します:** `to_is_open`（保存先が開いている図面）・`file_exists`（保存先が既に存在する）。いずれも
`internal` です（`invalid_args` と `internal` の区別は[ツール「共通の規則」](tools.md#共通の規則)）。
検証してから保存するまでの間にファイルが作成された場合は、SDK のエラーを `internal` で返します
（開いている図面でなければダイアログは表示されない）。

- **`to` の親のフォルダが無ければ（ファイルであれば）、`internal` で拒否します（`parent_missing`）。** SDK もダイアログを
  表示せずに拒否し（50331649）、フォルダは作成しませんが、理由を分かりやすくするために先に検証します。親のフォルダは
  `to` の最後の区切りまでです（ルートの直下の `to` ではルート。`C:\a.vwx` は `C:\`、`\\server\share\a.vwx` は `\\server\share\`）。
- **Windows の予約された名前（`CON.vwx` など）も、装置ではなくファイルの名前として問い合わせます。**
  Windows では `\\?\`（UNC は `\\?\UNC\`）を付けて問い合わせるので、予約された名前も装置の名前として解釈されず、
  `MAX_PATH` で失敗することもありません。`\\?\` は `.`・`..`・段の末尾の `.` と空白を解決しませんが、いずれも形式の検証で
  先に拒否しているので、問い合わせ先は Vectorworks が保存する先と同じです。但し、予約された名前を拡張子付きでも装置として
  扱う古い Windows（Windows 10 まで）では、`\\?\` を付けて問い合わせた検証は「無い」で通過するのに、Vectorworks は装置へ書き込んで
  成功を返します。Vectorworks 2026 が対応する Windows は Windows 11 のみ
  （[動作環境](https://www.vectorworks.co.jp/Support/sysreq/vw2026.html)）なので、この場合は扱いません（利用者の判断）。

## ネットワークの場所

**ネットワークの場所（ネットワークのドライブ・共有）の保存先では、サーバーに到達できないと Vectorworks が停止します。**
`save` の状態の検証（`file_exists`・`parent_missing`）と保存
そのものはメインスレッドで行うので、サーバーが停止している・ネットワークが切断されている場合は、OS が失敗を返すまで
待機し、その間は画面の操作にも CLI の他の要求にも応答しません。この振る舞いを許容します。
OS が失敗を返すまでの待機は、呼び出し元の既定の待機の上限（`vw2026 call` の 30 秒）を超えうるので、その場合は `call` が
「実行されたかもしれない」（終了コード 4）で終了し、下記の `to_check_failed` を読み取れません。ネットワークの場所へ保存する
場合は長い `--timeout` を指定し、終了コード 4 で終了したら、Vectorworks が応答するようになってから `documents` で確認します。
UNC のサーバーの名前を綴り誤った場合も、Windows は名前の解決を待機してから到達できない場合と同じ 53 を返すので同じ扱いになり、
終了コード 4 か `to_check_failed` で終了します（`parent_missing` にはならず、サーバーが停止している場合と区別できない）。

- **待機した後の失敗は「無い」と区別します。** 「無い」に数えるのは、mac は `ENOENT`・`ENOTDIR`、Windows は
  2 `ERROR_FILE_NOT_FOUND`・3 `ERROR_PATH_NOT_FOUND`・67 `ERROR_BAD_NET_NAME`（サーバーに共有が無い）・
  267 `ERROR_DIRECTORY`（途中の段がファイル）のみです。
  `to` の検証で OS の呼び出しがそれ以外の理由（ネットワークの失敗など。Windows の 53 `ERROR_BAD_NETPATH`・
  64 `ERROR_NETNAME_DELETED` など）で失敗した場合は、`file_exists`・`parent_missing` ではなく `internal`（`to_check_failed`）で拒否し、`detail` に OS の
  エラーの番号を整数で載せます（`{"reason":"to_check_failed","check":<段>,"os_error":<値>}`。`check` は失敗した検証で、
  `"to"`（`to` そのもの）か `"parent"`（親のフォルダ）。`os_error` は mac では `errno`、Windows では `GetLastError()` の値で、
  キーは OS に依らず同じ。いずれも必ず付与する）。呼び出し元がファイルやフォルダが削除されたと誤読しないためです。
- **`to` はリンクをたどらずに、親のフォルダはリンクをたどって問い合わせます。** 壊れたシンボリックリンクがある `to` は
  `file_exists`、リンク先の無いシンボリックリンクやジャンクションの親は `parent_missing` になります（OS 間で統一される）。
- ネットワークの場所そのものが切断されている場合（mac の `/Volumes` の下のマウントが外れた、割り当てた
  ドライブ文字が無い）は、OS がパスの無い場合と同じ番号（`ENOENT`・3）を返すので区別できず、「無い」になります。但し mac で、外れた後も
  `/Volumes` の下にマウント先の空のフォルダが残っていると、その直下の `to`（`/Volumes/share/a.vwx`）は親のフォルダが
  存在するように見え、起動ディスク上のそのフォルダへ保存されます（プラグインはマウントが外れたことを区別しない）。強制的に外した後にしか起きない稀な場面なので、`VW Backup` の
  警告と同様に、事前に検証せずに許容します。結果は成功で返るので、呼び出し元からも区別できません。
- **この「無い」の表は OS の振る舞いで、SDK リファレンスに根拠の節はありません**（CLAUDE.md の 7 の対象外）。mac と Windows の
  `VwCliTests` が本物の呼び出しで検証します（ファイルが無い・親のフォルダが無い・途中の段がファイル）。CI で作成できない
  共有が無い場合（67）と存在しないサーバー（53）は Windows の実機で確認しました（存在しない共有は `parent_missing`、存在しないサーバーは
  約 9 秒待機してから `to_check_failed` の 53）。表に無い番号が「無い」の場面で返れば、表に追加します。
- **保存そのものの途中で接続が切断された場合**に Vectorworks がエラーのダイアログを表示するかは、確認していません
  （[SDK の調査「調査しないと決定した事項」](../sdk-research.md#調査しないと決定した事項)）。表示された場合は、他のダイアログと同様に
  呼び出し元が扱います（[設計「本番環境で常駐させる前提（安全性）」](../design.md#本番環境で常駐させる前提安全性)）。

**停止することは SDK リファレンスでは調査しません**（OS の呼び出しがネットワークを待機することは SDK の挙動ではなく、停止するのは
明らかなので、利用者の判断で CLAUDE.md の 7 の例外とした。[SDK の調査「調査しないと決定した事項」](../sdk-research.md#調査しないと決定した事項)。
保存の途中で切断された場合のダイアログも同じ例外で、表示されればダイアログのコマンド（[#133](https://github.com/min-nano/vectorworks-plugin-command-line-interface/issues/133)）で扱うので、表示されるかどうかで実装は変わらない）。

## パスの一致の判定

`to` が開いている図面のパスと一致するか（`to_is_open`）の比較の方法です。`document` の一致（`documents` が返した
文字列との完全な一致）とは別です。

`to` は新しいパスで、開いている図面の保存先との衝突を**見逃さない側**に倒して
比較します: 絶対パスを必要とし（相対パスは `invalid_args`）、Unicode を正規化（NFC。mac のファイル名は
NFD で返ることがある）し、**大文字と小文字を区別せず**に比較します。大文字と小文字のみが異なる別のファイルも拒否する
ことになりますが、警告のダイアログが表示されるより安全です（ダイアログが表示されるのは文字列が完全に一致する場合のみなので、
緩く比較して拒否すれば必ずその手前で停止する）。ディスクに存在するファイルはこの比較の方法に依らず 2 つ目の検証で拒否するので、
この比較の方法は、開いている図面との衝突を `to_is_open` として示すためのものです（8.3 の短い名前と長い名前の違いは
ここでは区別せず、`file_exists` で拒否する）。

- **警告が表示されるのは、mac も Windows も文字列が完全に一致する場合のみです**（ファイルが無くても表示される。#288）。それでも
  緩く比較するのは、開いている図面のファイルを移動した後に、大文字と小文字・NFC と NFD のみが異なる `to` で同じファイルを
  指す 2 枚目が生じるのと、Windows で NFD の別のファイル（NTFS は区別する）に見た目が同じ図面が生じるのを防止するためです。
- **NFC への正規化と、大文字と小文字を区別しない比較は OS の呼び出しで行います**（mac は CoreFoundation の
  `CFStringNormalize`・`CFStringCompare`、Windows は `NormalizeString`・`CompareStringOrdinal`）。外部のライブラリは
  追加しません。
  - **畳み方は OS の呼び出しの通りで、mac と Windows で一部の文字が異なりえます**（`CFStringCompare` の
    `kCFCompareCaseInsensitive` は Unicode の case folding、`CompareStringOrdinal` の大文字と小文字の無視は OS の表での
    単純な大文字への変換。どの文字で異なるかは確認していない）。同じ `to` が一方の OS でのみ `to_is_open` になりえますが、
    この比較の方法は開いている図面との衝突を示すためのもので、ディスクに存在するファイルは `file_exists` で拒否し、警告が表示されるのは
    文字列が完全に一致する場合のみなので、差異を許容します。但し、開いている図面のファイルがディスクから移動されて
    いると、一方の OS でのみ一致する文字のみが異なる `to` は、もう一方の OS では `to_is_open` にも `file_exists` にも
    該当せずに保存され、見た目の近い図面がもう 1 枚生じえます。同じファイルを別の綴りで指す場合も、同様に見逃し
    えます。例えば、UNC から開いた図面とその共有に割り当てたドライブ文字の `to`、8.3 の短い名前と長い名前、`subst` の
    ドライブ、ジャンクション・シンボリックリンクを通る綴り、mac の `/var` と `/private/var` です（いずれも、開いている
    図面のファイルがディスクから移動されている場合のみ。ファイルが存在すれば `file_exists` で拒否される）。

## 実装とテストの分担

検証は `src/core` に配置し、**mac の規則と Windows の規則を別々の関数にして、いずれもどの OS でもビルドし、
どの OS の CI でも両方をテストします**（内容は文字列の処理のみで、OS で分割する必要がないため。Windows の規則にも
ASan・UBSan と clang-tidy が適用される）。プラグインがいずれを使用するかは `_WIN32` で選択し、選択するのは 1 か所のみです
（出荷するプラグインは OS ごとのビルドなので、各 OS のプラグインの規則はビルドで決定される）。ファイルの分割の方法は
[ブリッジ「分割の方針」](bridge.md#分割の方針)と `src/core/SaveTarget.h`・`src/core/PathCompare.h` の注釈にあります。

- **OS で分けてビルドするのは、比較の方法の包みと、ファイルシステムに問い合わせる関数の包みの 2 つのみです。** 検証の手順
  （`to_is_open` → `file_exists` → `parent_missing` の順）は両方を引数で受け取り、どの OS でもビルド・テストします
  （テストは 53 などの失敗を返す差し替えを渡す）。
- **比較の方法の包みは mac と Windows でのみビルドし、Linux 用の代替の実装は配置しません**（出荷しない実装をテストしても、
  出荷するものについて何も判明しないため）。包みのテストのファイルは OS で分割せずに `VwCliTests` に並べ、mac と Windows で
  包みが無ければコンパイルで停止します（包みの側の条件を誤って記述しても、テストが暗黙に抜けて CI が緑のままにならない
  ように。ファイルを OS で分割すると、そちらの条件の誤りはこの制約に届かない）。
- **プラグインの `save` が本物の比較の方法を渡していることは CI では検証できない**（結び付けは SDK に依存する `src/tools` の
  側）ので、実機で検証します（開いている図面と大文字と小文字のみが異なる `to` が `to_is_open` になることを mac と
  Windows で、NFC と NFD のみが異なる `to` が `to_is_open` になることを mac で確認した）。`save` の結び付けを変更したら、
  実機で再確認します。
