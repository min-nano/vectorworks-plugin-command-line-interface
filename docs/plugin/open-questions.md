# 決まっていないこと

番号は他のページから参照しています。決まったら該当のページへ書き込み、ここから消します。

## 1. 受け付けの停止と再開

本番で常駐するので、利用者が受け付けを止める手段を用意します（[設計「本番で常駐させる前提」](../design.md#本番で常駐させる前提安全)）。

- **案 A（推奨）**: メニュー「CLI ブリッジの状態…」で停止・再開を切り替え、**利用者ごとの
  設定ファイル**に残す（mac `~/Library/Application Support/vectorworks-cli/settings.json`、
  Windows `%APPDATA%\vectorworks-cli\settings.json`）。プラグインのフォルダには置かない
  （更新でフォルダごと入れ替わる）。既定は「受け付ける」。
- 案 B: 停止は Vectorworks を終了するまで（残さない）。
- 案 C: 停止の手段を持たない（アンインストールで止める）。

## 2. 表示名

メニューのカテゴリと、コマンドの表示に出る名前。例: 「Vectorworks CLI」「みんなの CLI」。
開発版はその後ろに `Dev` を付けます。

## 3. 図面に書く道具の作法

書く道具（種類 `write`）を足す前に決めること。

- undo の単位（要求 1 件＝ undo 1 つ）と、その名前（`vw2026: <道具>` など）
- 人が図面を操作している最中に届いたときの扱い（OS タイマーは undo の記録が開いている間は
  見送るが、ダイアログを開いている最中などは別に考える）
- 書いてよい対象の限定（利用者の名前付きリソースを作らない・書き換えない、など）

## 4. Vectorworks の版の違うプラグインの同居

コマンド名は `vw2026` ですが、スプールの名前（`vectorworks-cli-bridge`）には版が入っていません。
将来 2027 用のプラグインが出て、**2026 と 2027 を同時に起動する**と、2 つの橋が同じスプールを
読みます（どちらが要求を取るか定まらない）。

- **案 A（推奨）**: スプールに版を入れる（`vectorworks2026-cli-bridge`）。コマンドと対になる。
- 案 B: 名前はそのままにし、生存の印に `vectorworks`（版）を載せ、`vw2026` は版の違う橋を
  使わない。同時起動の衝突は残る（後から起動した側は、生きている印を見つけたら受け付けない、で避ける）。

## 5. 自動レビュー

元の `pr-review.yml` を移すなら、リポジトリの Secrets に `CLAUDE_CODE_OAUTH_TOKEN` が要ります。
移さないなら Secrets は不要です（SDK の取得もリリースも `GITHUB_TOKEN` で足りる）。

## 6. main の保護に切り替える時機

いまは `main` へ直接 push しています。段 2（骨格）から実機確認の要る PR が始まるので、
その前に保護して PR で進めるのがよいと考えます。
