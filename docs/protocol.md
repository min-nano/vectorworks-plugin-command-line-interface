# 受け渡しの作法（protocol 1）

ブリッジ（プラグイン）と呼ぶ側（`vw2026` や、作法を守る任意のプログラム）は、**ローカルの
ディレクトリ 1 つ（スプール）に置くファイル**でやり取りします。この文書が作法の真実で、
プラグイン側（C++）と CLI 側（`cli/internal/spool`）はその対になる実装です。**どちらかを
変えたら、この文書と両方を直してください。** 形を変えたら版（`protocol`）を上げます。

作法は、構造設計支援プラグイン（`vectorworks-plugin-import-ifc-homeskz`）の開発版の MCP
ブリッジ（M24〜M42）で実機で確かめた作り（`src/core/Bridge.h`）を引き継いでいます。違いは
末尾の「元の作法との違い」にまとめています。

## スプールの場所

```
<一時ディレクトリ>/vectorworks2026-cli-bridge/       … 安定版
<一時ディレクトリ>/vectorworks2026-cli-bridge-dev/   … 開発版
```

- **名前に Vectorworks の版を入れます。** 版ごとにプラグインを入れるので、2026 と 2027 を
  同時に起動しても、2 つの橋が同じ要求を取り合わない（コマンド `vw2026` と対になる）。
- 安定版と開発版のプラグインが同居しても取り違えないよう、開発版は別の名前にします。
  呼ぶ側は系列（`stable` / `dev`）で選びます。
- **プラグイン側は自分の一時ディレクトリへそのまま置きます**（探索しない）。macOS では
  利用者ごとの `/var/folders/…/T/`、Windows では `%TEMP%`。
- **探すのは呼ぶ側の役割です。** 一時ディレクトリは環境変数で決まるので、GUI アプリの
  Vectorworks と、ssh や別のアプリから起動されたプロセスとで食い違いえます。呼ぶ側は次の順に
  候補を調べ、**有効な生存の印があるところ**を使います。
  1. 利用者ごとの一時ディレクトリ（macOS の `getconf DARWIN_USER_TEMP_DIR`）
  2. 自分の一時ディレクトリ・`TMPDIR`・`TMP`・`TEMP`
  3. ただし macOS で 1 が取得できたなら `/tmp` は調べない
- **推測による候補は持ちません**（`/tmp` への退避や `/var/folders` の総当たりはしない）。
  場所が分かっているなら環境変数 `VW2026_SPOOL` で明示します（両側で同じ値にする）。

### 持ち主と権限

- プラグイン側は**自分の所有・0700** で作り、既にあるものは持ち主と権限を確かめてから
  使います（POSIX）。他の利用者のもの・他から書けるものは使いません。
- 呼ぶ側も同じ基準で判定し、合わない場所は使いません。理由: `/tmp` のような誰でも書ける
  場所に偽の印を置かれると、要求（引数）が漏れ、偽の応答を受け取ります。
- Windows の `%TEMP%` は利用者ごとなので、存在だけを確かめます。

## ファイル

| ファイル | 書く側 | 中身 |
| --- | --- | --- |
| `bridge.json` | プラグイン | 生存の印 |
| `<id>.req.json` | 呼ぶ側 | 要求 1 件 |
| `<id>.res.json` | プラグイン | 応答 1 件 |
| `*.tmp` | 両方 | 書きかけ（下記） |

**どのファイルも、同じディレクトリへ `<名前>.tmp` として書いてから rename で公開します。**
読み手に書きかけの内容を読ませないためです。読み手は、読めない・JSON として壊れている
ファイルを「まだ無い」とみなして読み直します。

### id

- 綴りは `[0-9A-Za-z_-]{1,64}`。**プラグイン側はこれを満たさない id を受け付けません**
  （ファイル名に使うので、`../` を混ぜてスプールの外へ書かせないための関門）。
- プラグイン側は要求を**ファイル名の昇順**で処理します。呼ぶ側は、名前の昇順が送った順に
  なる id を付けます。`vw2026` は `<UnixNano を 19 桁>-<乱数 8 桁の 16 進>` で、別々の
  プロセスからの要求も送った順に並びます。

## 生存の印（`bridge.json`）

```json
{"plugin":"cli","channel":"stable","version":"abcdef0","branch":"main","protocol":1,"beat":1760000000,"pid":4242}
```

| フィールド | 意味 |
| --- | --- |
| `plugin` | プラグイン名（`cli` / `cli_dev`） |
| `channel` | 配布の系列（`stable` / `dev`） |
| `version` | 受け答えをしている本体の版（短い sha。殻と本体の入れ替えを確かめる手掛かり） |
| `branch` | 本体を作ったブランチ |
| `protocol` | この作法の版。呼ぶ側は一致しなければ要求を置かない |
| `beat` | 最後に書き直した時刻（epoch 秒）。プラグイン側は数秒ごとに書き直す |
| `pid` | Vectorworks のプロセス ID |
| `busy` / `busy_id` / `busy_until` | 長く走る道具の最中だけ。道具の名前・処理中の要求の id・いつまでかかりうるか（epoch 秒） |

- **`beat` が 15 秒より古ければ「動いていない」**と判定します。ただし `busy_until` が
  未来なら動いているとみなします（長く走る道具の最中、プラグインは印を書き直せない）。
- 呼ぶ側は、待つ上限を過ぎても `busy_id` が自分の要求で `busy_until` が未来なら待ち続けます。
- プラグイン側は止まるときに印を消します。異常終了すると印は残りますが、古びるので
  「動いていない」と判定されます。

## 要求（`<id>.req.json`）

```json
{"id":"1760000000123456789-0a1b2c3d","tool":"layers","args":{"include_sheets":false}}
```

- `id` はファイル名の `<id>` と一致させます。食い違う要求はエラーで応答されます。
- `args` はオブジェクト。省略・オブジェクト以外は `{}` として扱います。
- 1 件の上限は **1 MiB**。超えるものは「読めない要求」としてエラーで応答されます。

## 応答（`<id>.res.json`）

```json
{"id":"…","ok":true,"result":{…}}
{"id":"…","ok":false,"error":"知らない道具です: nope"}
```

- 呼ぶ側は応答を読んだら消します。
- 待つのを諦めた呼ぶ側は、置いた要求を消して取り下げます（あとで読み取られて、誰も待たない
  応答が残らないように）。

## プラグイン側の義務

- **要求は読めても読めなくても、まず消します**（残すと毎回取り出し直す）。読めなかった
  要求にも、ファイル名から取り出した id が正しければエラーで応答します（呼ぶ側を待たせ切らない）。
- 1 回の受け付けで処理する件数に上限を設けます（溜まっていても Vectorworks を占有し続けない）。
- **開始時に、前の回の残骸（要求・応答・書きかけ）を消します。** ただし有効な生存の印が
  あるとき（本体を入れ替えただけで、橋は続いている）は消しません——入れ替えの直前に
  書いた応答や、置かれたばかりの要求まで消すことになります。
- 道具 1 つの失敗（例外を含む）で橋を止めません。

## 予約された道具

| 道具 | 結果 |
| --- | --- |
| `tools` | `{"protocol":1,"tools":[{"name":…,"description":…,"inputSchema":{…},"kind":…,"timeoutSeconds":…}]}`。`inputSchema` は JSON Schema。`kind` は `read` / `write` / `long` / `shell`（図面を変えるか・殻が処理するかを呼ぶ側が判定できるように）。`timeoutSeconds` は既定より長くかかりうる道具だけ |

道具の名前は `[a-z0-9_]+(\.[a-z0-9_]+)*`。プラグインが自分で持つ道具は接頭辞なし
（`ping` / `layers` …）、ほかのプラグインの機能を呼ぶ道具は `<提供者>.<名前>` にする予定です
（[設計「他のプラグインの道具」](design.md#他のプラグインの道具)。呼び出しの手段は SDK の調査待ち）。

## 元の作法との違い

構造設計支援プラグインの MCP ブリッジ（protocol 1）からの変更点です。この作法は新しい
プラグインのもので、元のものとは**別の版の系列**です（スプールの名前も違うので混ざりません）。

| 項目 | 元 | ここ |
| --- | --- | --- |
| スプールの名前 | `<プラグイン名>-mcp` | `vectorworks2026-cli-bridge`（`-dev`）（MCP 専用ではない） |
| 場所の明示 | `VW_MCP_SPOOL` | `VW2026_SPOOL` |
| 道具の一覧 | `vw_tools` | `tools` |
| 道具の名前 | `vw_` 接頭辞 | 接頭辞なし・提供者は `.` で区切る |
| 生存の印 | `commit` / `branch` / `served` / `failed` | `channel` / `version` / `branch` / `pid`（数は印に載せない） |
| 長く走る道具 | `busy` / `busy_until` | それに `busy_id` を加える（呼ぶ側が自分の要求か判定できる） |
| id | 連番＋乱数（1 プロセス内の順） | 時刻＋乱数（プロセスをまたいで送った順） |
